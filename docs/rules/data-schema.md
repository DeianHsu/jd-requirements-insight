# 数据合同与业务语义规则

本文规定 Agent 处理项目术语、抽取数据合同、数据库结构和标注语义时必须遵守的通用边界。

## 1. 权威来源

1. `docs/GLOSSARY.md` 是全项目术语、固定含义、禁止误用和跨阶段不变量的唯一信息源。
2. `docs/annotation/` 是职责、岗位要求、证据、人工标准答案和数据集评测语义的完整规范。
3. 已提交代码合同与自动化测试是实现事实；`app/schemas.py`定义抽取数据合同，`app/models.py`和`app/database.py`定义数据库结构与迁移行为。
4. 发现新术语、同词异义或定义冲突时先更新 GLOSSARY，再同步 Design、代码、测试和人类文档；不得在单个功能中另行约定含义。

## 2. 定点读取

- 处理职责时读取 `docs/annotation/RESPONSIBILITIES.md`。
- 处理原子要求、类别、重要程度、熟练度、逻辑组或年限时读取 `docs/annotation/REQUIREMENTS.md`。
- 处理证据、人工标准答案、开发集、回归集、验证集或评测指标时读取 `docs/annotation/DATASET_EVALUATION.md`。
- 只读取与当前 P0 和具体目标相关的章节；语义存疑或发生冲突时再扩大上下文。

## 3. 跨阶段不变量

1. P0-1定义抽取数据合同和标注规则，不直接产生业务数据。
2. P0-2按整份JD执行结构化抽取，职责与候选人要求不得混用。
3. P0-3验证和改进原子化粒度，不定义另一套输出类型。
4. P0-4输入是要求实例；`ResponsibilityItem`本身不参与要求归并。
5. P0-4不得覆盖或删除`raw_name`、类别、重要程度、熟练度、逻辑组、年限、证据或抽取置信度。
6. 同义表达归并到同一标准要求项；`is_a`、`part_of`和`related_to`只建立关系，不触发归并。
7. P0-4代码和Prompt保持领域无关，不硬编码具体领域技能。
8. P0-6才按独立JD数去重统计；P0-7通过要求映射回溯要求实例、证据和原始JD。
9. 人工标准答案不得为迎合模型输出而修改；已用于调参的数据不得重新宣称为未见验证集。
10. 证据存在性不等于证据支持性，自动指标不得替代需要人工复核的语义判断。

## 4. Schema 变更

修改公共接口、Pydantic Schema、枚举、数据库字段、索引、约束或数据语义前，必须确认 Design 已明确授权；否则由 Developer 提交 Change Request。变更时同步检查合同、ORM、迁移、标注规范、测试、术语和受影响消费者。
