# 代码质量规则

本文规定项目代码、注释和功能目录说明的通用质量要求。

## 1. 中文说明

1. 每个代码文件必须包含中文模块说明。
2. 公共类、函数和方法必须包含中文文档字符串；私有辅助函数按复杂度和维护需要决定。
3. 注释重点说明职责、边界和设计原因，不逐行翻译代码。
4. 不直观代码块按需补充中文注释；修改行为时同步检查并移除过时说明。

## 2. 实现边界

1. 修改范围必须符合当前 Design；无关重构不得混入当前 P0。
2. 能复用现有合同、解析、查询和评测能力时不得在实验脚本中复制实现。
3. 公开类、枚举、CLI、文件和标题新增或改名时，先检查 `docs/GLOSSARY.md`和既有命名。
4. 缺陷修复应先建立能够复现问题的确定性测试，再修改行为。

## 3. 目录 README

1. 每个包含功能代码的目录和测试目录应有面向人类的 `README.md`。
2. README 说明目录用途、文件职责、模块关系、数据流或运行方式；不得承担 Agent 路由、角色权限、Change Request 或强制开发流程。
3. 新增、删除或重命名代码文件时同步更新所在目录 README 的文件索引。
4. Agent 行为要求只维护在 `AGENTS.md`、角色文档和 `docs/rules/`，README 最多提供面向人类的规范链接。
