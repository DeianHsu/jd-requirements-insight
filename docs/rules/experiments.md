# 实验与正式验收规则

本文规定实验脚本、外部模型调用、临时验收、正式验收和报告材料的边界。

## 1. 实验入口

1. 实验性Python脚本统一放在`scripts/experiments/p0_x/`，不得放在项目根目录。
2. 可复用的数据合同、解析、评测、数据库查询和业务逻辑必须进入`app/`并补自动化测试；实验脚本只负责参数解析、调用正式模块和保存结果。
3. 每个脚本必须包含中文模块说明、公共函数中文文档字符串、`main()`和`if __name__ == "__main__"`保护。
4. 导入实验脚本不得读取配置、连接数据库、写文件或调用外部服务。
5. 脚本路径、文件职责和面向人类的运行方式由`scripts/experiments/README.md`及对应P0目录README说明。
6. 受Git跟踪的实验脚本不得内嵌真实JD句子、人工标准答案、判断说明或原始模型响应；需要这些材料时只能从`data/private/`读取，并在输出中保持脱敏。

## 2. 外部调用和数据库

1. 有费用的外部调用必须由用户明确授权，并要求显式`--execute`。
2. 数据库操作必须显式选择项目数据库或指定`--database-url`，不得隐式写入项目数据库。
3. 运行前输出模型、输入范围、预计调用次数和脱敏后的目标类型；不得输出密钥或完整远程连接串。
4. 小规模预检不自动授权后续全量调用，每次跨入付费或正式验收阶段都必须符合 Design 和用户授权。

## 3. 验收分层

临时验收同样遵守“静态检查 → 小规模验证 → 全量回归 → 版本确认”。小规模预检不计正式验收次数，不得据此标记P0完成。

正式验收必须预先固定范围、指标和通过标准，并在当前 Develop 记录：

- 日期；
- 代码、模型、Prompt和Schema版本；
- 输入范围；
- 指标与结果；
- 失败原因；
- 当前连续失败次数；
- 详细报告路径。

同一目标连续3次正式验收失败时，必须暂停继续修复和付费调用，在 Develop 与 Review 记录当前阻塞和恢复条件，等待用户重新授权。新的授权开始新的计数周期，但历史失败保留在 Git 和报告中，不在当前文档堆叠流水。

## 4. 报告与私有材料

- Develop 只保存实验摘要、关键指标、主要结论和当前报告路径。
- 脱敏后的详细分析按P0放入`reports/P0-X/`；现有报告含困难样例或真实语义细节时继续保持Git忽略。
- 原始模型响应、完整JSON、真实JD、人工标准答案、含真实证据的失败案例和运行日志放入`data/private/experiments/P0-X/`，不得进入Git。
- 只有Prompt版本、人工标准答案冻结状态或阶段结论发生实质变化时才更新阶段报告；普通调试日志不进入报告。

## 5. 实验结束

实验结束后，可复用能力迁入正式模块和CLI；仍需复现的脚本保留，不再需要的脚本删除。同步更新代码目录README、当前Develop、报告入口和忽略规则，但不得把实验脚本变成未声明的正式业务入口。
