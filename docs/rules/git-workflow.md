# Git与发布规则

本文规定Agent使用Git、建议提交和保护私有信息的边界。

## 1. Git权限

1. Agent可以读取`git status`、`git diff`、`git log`、`git show`和忽略状态，以确认实现事实和保护用户改动。
2. Agent不得擅自执行`git commit`或`git push`，不得改写历史或强制推送；未经用户明确要求也不执行`git add`。
3. 达到合理提交节点时，Agent应停止并向用户提供：建议提交范围、Summary、Description、验证结果和未提交风险。
4. commit和push均由用户手动执行；更新Design、Develop或Review不表示已经提交或发布。

## 2. 建议提交格式

- **范围**：只列本轮相关文件，明确排除私有数据和无关工作树改动。
- **Summary**：一句话说明本次可独立理解的结果。
- **Description**：列出主要变化、设计边界、验证结果和必要迁移信息，不复制实验日志。
- **验证**：说明实际运行的检查；未运行的测试或实验必须明确写出。

## 3. Git跟踪范围

正式Agent规则、角色、Design、Develop、Review、模板、术语、项目计划、决策、标注规范、代码、测试和人类README应进入Git。下列内容禁止进入Git：

- `.env`、API密钥、访问令牌和远程连接凭据；
- 真实JD正文、人工标准答案、真实简历和个人求职材料；
- SQLite数据库；
- 完整模型响应、含真实证据的失败案例和私有实验日志；
- 虚拟环境、缓存和构建产物；
- `data/private/`中的全部内容。

报告是否跟踪以隐私审计为准；包含困难样例、真实语义细节或可能还原JD内容的报告继续忽略。

## 4. 发布前检查

1. 检查`git status`和待提交差异，只建议本次预期文件。
2. 使用`.gitignore`和`git check-ignore`确认私有数据、数据库、缓存和凭据未进入范围。
3. 搜索密钥、令牌、本机绝对路径、真实简历、JD正文和完整证据等敏感内容。
4. 确认公开README和受跟踪文档不链接仅存在于某台机器的私有文件；Develop允许把明确标注为本地私有材料的路径作为开发恢复入口。
5. 功能代码发布前确认必要测试和Ruff；纯文档发布检查内容、链接、格式、依赖、忽略规则和敏感信息。

## 5. 隐私事件治理

1. Tech Lead负责只读确认受影响的当前文件、路径、commit和远端范围，并直接修正规则、文档、README、报告入口、`.gitignore`和其他Git跟踪边界。
2. 对当前受跟踪文件中的私有内容，Tech Lead可以删除、脱敏或隔离以立即停止继续暴露；若文件同时承载可执行逻辑，替代实现和测试由Developer负责。
3. 私有内容已经进入Git历史或远端时，普通删除commit只能修正当前版本，不能清除历史；Tech Lead应给出待清理路径、commit范围、风险和验证方法。
4. 历史改写、强制推送、commit和push仍由用户决定并手动执行；未完成远端与协作者副本处理前，不得把事件标记为已彻底清理。
5. API Key、访问Token、密码、个人隐私、客户机密和受合同限制的数据属于不可接受暴露：必须立即撤销或轮换、停止传播，并按影响范围执行历史与远端清理，不得以风险接受替代。
6. 不含凭据、个人隐私或第三方机密的自制实验样例与人工标注，可在当前版本完成删除、防复发约束和范围审计后，由用户明确接受旧历史残余风险；Tech Lead必须在Review中记录材料类型、接受依据和仍然存在的暴露范围。
