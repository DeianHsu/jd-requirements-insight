# 生产验收协议（Production Audit）

updated_at: 2026-08-07

本项目唯一正式的生产验收方法。等级由**检查对象和影响范围**决定，不看触发
关键词（"完整检查单个提交"与"完整检查整个生产主线"等级不同）。普通提交检查、
单点 bug 修复、测试失败排查、小范围 review 走局部检查，不读本文。

## 1. 审计等级（按对象选择，不看关键词）

| 等级 | 适用对象 | 内容 |
|---|---|---|
| L1 提交检查 | 普通提交、局部修复、单点 bug、测试排查、完整检查单个提交 | diff review、相关测试、局部合同核对；不做全链路追踪 |
| L2 模块关闭验收 | **单个模块关闭（默认 L2）**、模块内部 artifact 传递 | artifact tracing（正常路径 + 关键失败路径）、测试真实性、文档同步 |
| L3 生产主线审计 | 正式生产主线、跨模块架构变更、正式数据发布 | 完整端到端、上下游 provenance、数据库副作用、批量/单条兼容、幂等与事务、代表性反例、真实产物验证 |

**L2 升级 L3 的条件**（满足任一即升级）：

- 跨模块 artifact 传递；
- 正式数据库写入；
- provenance 或审核身份；
- 数据迁移；
- 付费模型结果正式化；
- 对外报告或发布。

本文主体是 L3 方法；L2 可裁剪第 7、10 节。触发后按对应等级和第 11 节输出。

## 2. 不信任声明原则

`PROJECT_PLAN.md`、`CURRENT_STATE.md`、README、提交信息、测试名称中的
"已完成、闭环、达标、通过"一律视为**待验证声明**，必须用代码和实际执行重新
证明。实现存在 ≠ 流程通；测试绿 ≠ 正式入口被调用；文档写完成 ≠ 完成。

## 3. Artifact tracing（核心）

选**代表性产物**（不穷举全部历史）：一个正常路径产物、一个批量场景、一个
失败/异常场景。沿正式路径逐站追踪：

```text
JD 导入 → 抽取候选 → 验收 → 人工审核 → finalize-extraction
→ 归并候选 → 稳定性验收 → 人工裁决 → finalize-consolidation → generate-report
```

每站强制回答：

- 上一步输出是否**直接**是这一步输入？（找不到消费方 = 断点；用 grep 验证写方/读方）
- 是否需要手工改中间 JSON 才能衔接？
- 是否重复调用付费模型（候选被浪费）？
- 身份字段（run_identifier / job_ids / 指纹）是否无损传递？
- 批量与单条模式是否兼容？
- 中途失败会不会留下正式数据或半成品？

## 4. 测试真实性检查

对关键 E2E/集成测试逐行检查：

- 是否调用正式入口（真实 CLI 命令、真实验收脚本）？
- 是否手工构造 report/raw/审核文件？（夹具手工构造本身合理；**只有测试声称
  证明正式流程闭环却绕过真实入口**才是问题，必须标注为"未证明正式链路"）
- 测试数据形态是否覆盖真实操作方式（批量验收、多 JD）？

## 5. 上下游门禁与 provenance

每个安全门必须检查上下游覆盖：归并定稿门禁是否验证上游抽取来源绑定？
报告门禁是否验证归并层完整定稿字段？"本层已定稿但上游未绑定"的状态必须
显式报告，不得用本层 reportable 推断整条链。

## 6. 代表性反例预算

优先构造 **3～5 个最高风险反例**：身份混用、范围不一致、部分失败、重复执行
（幂等）、上游缺失。发现 blocker 后**停止穷举**，记录剩余未检查范围。

## 7. 证据等级

- **blocker**：必须附代码证据（`file:line`）或运行证据（命令 + 输出）；
- **非阻塞项**：至少一个定位依据；
- **假设**：明确标注"待验证"，不得作为方案依据。没有数据支撑的预测
  （增长曲线、阈值、效果估计）一律归入假设或提出验证实验。

## 8. 结论四层分类

1. 当前基线 blocker（当前数据/功能能否使用）；
2. 下一阶段 blocker（进入下一目标的前置条件）；
3. 长期规模化风险（需要数据验证的假设）；
4. 非阻塞卫生项。

## 9. 停止条件

- **出现 P0 blocker 后**：只继续检查与该 blocker 同一链路的直接影响；不自动
  扩展到无关模块；记录剩余未检查范围；
- **正常结束条件**（全部满足）：正式路径每一站有明确生产者与消费者；代表性
  正常路径通过；最高风险失败路径有门禁；关键 E2E 未绕过正式接口；结论均有
  证据等级。

## 10. 红旗清单（调查信号，不自动判定失败）

红旗只要求**调查与解释**，结合文档声称的用途判定，不自动构成 blocker：

- 文档出现"合成/模拟/手工"字样（如"合成端到端测试"）；
- 测试手工拼中间产物（见第 4 节判定）；
- 产物只有写方没有读方（纯导出/给人看的产物可能合理）；
- 两个事实并列但隐含矛盾（如 unverified 抽取 + reportable 批次）：必须存在
  **结构化、范围明确、可审计的 legacy waiver** 才能通过——豁免记录至少包含：
  被豁免的具体记录、不能满足新合同的原因、现有证据、批准人、允许消费的
  下游、是否仅限当前批次、新增数据禁止继续使用同类豁免。仅有普通状态说明
  （如 CURRENT_STATE 的文字描述）不构成正式豁免，仍需报告风险；
- 批量/单条模式不兼容；
- 门禁不检查上游 provenance。

## 11. 输出模板

```text
## 结论
- 检查目标是否达成（哪些声明被证实 / 哪些仍是待验证）

## 1. 当前基线 blocker
## 2. 下一阶段 blocker
## 3. 长期规模化风险
## 4. 非阻塞卫生项
## 5. 最小修复顺序（不改代码，除非用户授权）
```

每个 blocker 附证据并标注证据等级（代码/运行/假设）。

## 执行边界

- **默认只读正式数据**：不修改正式数据库、正式数据和正式报告；
- **允许最小临时产物**：临时 SQLite、临时 JSON、临时报告、测试目录——用于
  验证真实链路，完成后清理或留在 `.pytest-tmp` 等被忽略位置；
- 不调用付费模型；数据库操作必须显式选择目标（临时库用 `--database-url`）；
- 输出修复顺序但不实施，除非用户授权。
