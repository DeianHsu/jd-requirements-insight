# JD Skill Insight 核心术语

本文是项目术语含义的唯一信息源。代码、测试、计划、决策和 README 必须使用下列标准术语；发现新术语、同词异义或定义冲突时先更新本文，再同步受影响内容。本词典只固定容易导致业务语义漂移的核心术语，不复制代码类名、字段镜像、数据库表定义或完整枚举；这些内容以 `app/schemas.py`、`app/models.py` 和标注规范为准。

## 数据与抽取

| 标准术语 | 固定含义 | 不表示 |
|---|---|---|
| JD | 一份岗位描述，是正式结构化抽取、持久化和后续统计的来源单位 | 一个困难样例或一条岗位要求 |
| 职责 | 入职后需要完成的一项可独立描述或验收的工作；`ResponsibilityItem` 保存名称和证据 | 候选人需要具备的条件 |
| 岗位要求 | 公司对候选人的一项技能、经验、学历、专业、行业知识或软能力条件 | 只表示技术技能，或岗位职责本身 |
| 证据 | JD 原文中连续出现、能够支持职责或岗位要求及其字段判断的最小充分文本 | LLM 改写、跨段拼接、映射理由或要求关系依据 |
| 内容哈希 | 对 JD 正文执行 Unicode NFKC 与空白规范化后计算的 SHA-256，用作内容级去重标识；规范化只作用于哈希输入 | 修改数据库中的 JD 原文，或按文件名去重 |
| 抽取器版本 | `model_name + prompt_version + schema_version` 组成的抽取结果身份，用于幂等保存和版本比较 | 单独的 Prompt 版本、数据库结构版本或一次运行 ID |
| 正式JD样本范围 | P0-8 按当前筛选条件冻结的 15～20 个唯一已持久化 JD 集合；私有清单显式记录选中项、内容哈希、来源、筛选依据和共同抽取器版本 | 一次批量导入、数据库中的全部 JD 或具有总体统计代表性的市场随机样本 |

## 原子化与归并

| 标准术语 | 固定含义 | 不表示 |
|---|---|---|
| 原子要求 | 按原子化规则表达的一条 `RequirementItem`，只包含一个可独立学习、分类、评价、匹配或统计的条件；固定复合要求可以整体保留 | 必须压缩成单个技术词，或跨 JD 共享的标准要求项 |
| 固定复合要求 | 已形成稳定整体含义，或拆分后会改变招聘条件原意的复合表达，例如“数据结构与算法”；是否整体保留按原子化规则判断 | 任意包含“和”“与”或顿号的长要求 |
| 要求实例 | 某份 JD、某个抽取结果中的一条具体原子要求，带原始名称、属性、逻辑组、年限、证据和置信度 | 跨 JD 共享的标准要求项 |
| 跨JD原子要求归并与映射 | P0-4 汇总选定范围内的全部要求实例，收敛跨 JD 统计口径，并为每条实例保存可追溯映射 | 合并岗位职责、删除原始要求或在抽取阶段改写 `raw_name` |
| 标准要求项 | 多个语义相同的要求实例共同指向的跨 JD 统计口径；可以表示技能、经验、学历、专业、行业知识或软能力 | 覆盖或删除原始要求实例 |
| 要求映射 | 要求实例到标准要求项的可追溯关联，保存处理状态、映射理由和置信度 | 修改 `raw_name`、抽取属性或原始证据 |
| 归并输入指纹 | 对选定 JD、共同抽取器版本、抽取记录和完整要求实例执行确定性序列化后计算的 SHA-256；与范围键、归并器版本共同构成归并批次身份 | 归并器版本、内容哈希或可跨数据库引用的公开 ID |
| 要求关系 | 标准要求项之间的包含关系，唯一正式类型 `broader_than`（方向固定：更宽泛 -> 更具体，统一表达旧概念的 `is_a`、`part_of`、上下位、整体/组成）；等价由多个实例映射到同一标准要求项表达，不保存边；无关系不持久化；`uncertain` 是模型判断状态，不创建正式边 | 同义归并（映射表达）、无方向或模糊关系 |
| 同一要求 | 表面名称不同但结合证据上下文后指向同一招聘条件；例如明确语境中的缩写、中英文名称和同义表达 | 上下位、组成或仅相关关系 |
| 独立JD计数 | P0-6 按标准要求项统计包含该项的不同 JD 数量；同一 JD 内多个要求实例只计一次覆盖 | 在 P0-4 删除同一 JD 内的重复要求实例 |

## 标注与评测

| 标准术语 | 固定含义 | 不表示 |
|---|---|---|
| 人工标准答案 | 经人工确认并冻结的期望结果；完整 JD 的人工标准答案由 `GoldenExtractionRecord` 绑定来源文件与期望抽取结果。**自 DEC-015 起降级为 legacy 历史材料**：不再作为正式 Prompt 验收门槛，只用于历史比较和案例分析 | 当前正式验收真值、规则制定或违规审计的替代 |
| legacy Gold 数据 | 旧人工完整标注（`annotation_cases.json`，标记 `protocol=legacy_gold`、`status=historical`、`official_gate=false`）与 F1 报告；命令可复现历史结果但不得用于批准新的 Prompt | 当前正式验收依据 |
| 困难样例 | 从真实 JD 中选出的一个困难句子评测单元，包含人工期望的职责或岗位要求列表（legacy 材料） | 正式抽取单位、单个技能、整份 JD 或完整 JD 人工标准答案 |
| 名称代理指标 | 困难样例先用证据定位句内输出，再以保留专有英文技术词边界的确定性名称相似度做一对一匹配所得的 Precision、Recall 和 F1；**legacy 指标**，名称相似度在新协议中只作 diagnostic | 人工语义复核、要求映射准确率或证据支持性判断 |
| 规则场景 | 领域中性的基础输入 + 确定性变换 + 期望属性，用于变形测试；不保存完整 expected extraction | 完整人工标准答案、单元测试 expected output |
| 变形测试 | 对同一基础输入应用确定性变换后比较两次抽取，检查事实集、块集合与字段不变性 | 多次运行稳定性或人工审计 |
| 多次运行稳定性 | 相同输入独立运行 ≥3 次，以候选块为锚点报告块对齐、kind/字段一致性与漂移；第一版只作 warning，阈值待用户裁决 | 语义准确性证明 |
| 人工违规审计 | 人工按规则 ID 检查输出是否违反规则、证据是否支持结论，记录 `rule_id`/`violation`/`severity`/`evidence`/`reason`/`recommended_action` | 自动字符串包含检查、对照唯一答案打分 |
| 证据存在性 | 单条证据经允许的文本规范化后可在对应 JD 原文中找到 | 证据足以支持结论或边界最小 |
| 证据支持性 | 单条证据确实足以支持抽取名称和字段判断；证据最小性作为同一人工复核中的边界要求 | 自动字符串包含检查 |
| 熟练度（三级） | Schema V3 抽取枚举：`unknown`（无明确程度或仅经验类表达）/ `basic`（了解、理解、熟悉、能够使用）/ `advanced`（掌握、熟练、扎实、精通、专家级）；原始程度词保留在 evidence，枚举只表达粗粒度岗位门槛（DEC-016） | 候选人真实能力、`none`（完全不会，属未来个人能力层）、旧五级值（读取时确定性映射） |
| 开发集 | 已用于调整 Prompt、抽取数据合同或规则的样例分组；代码值为 `development`（legacy 分组） | 未见验证集 |
| 回归集 | 已经暴露给设计或调参过程、保留下来检查已知能力是否回退的样例分组；代码值为 `regression`（legacy 分组） | 可以继续宣称为未见验证集 |
| 验证集 | 按预先规则选择并经人工批准冻结、用于报告泛化结果的未见样例；代码值为 `validation`（legacy 分组）。一旦据其错误调参，该批数据不再承担下一轮正式验证职责 | 临时草案或开发集改名 |
| 临时验证 | 开发中针对当前代码或 Prompt 版本执行的阶段验证，用于决定是否继续；必须记录范围和结果，但本身不等于 P0 完成 | 正式验收、自动化测试或未记录的临时试跑 |
| 正式验收 | 按事先固定的完整范围、门槛和通过标准执行并计次的验收运行；抽取侧当前采用规则符合性 hard gate + 稳定性 warning + 变形测试 + 人工违规审计（DEC-015） | 小规模预检、单个规则场景通过或技术骨架完成 |

## 项目范围

| 标准术语 | 固定含义 | 不表示 |
|---|---|---|
| MVP | 当前求职作品版的最小可信闭环，以 `docs/PROJECT_PLAN.md` 列出的范围和验收标准为准 | 完整招聘产品、自动投递 Agent 或所有长期功能 |
| P0-N | `docs/PROJECT_PLAN.md` 中 P0 核心闭环的第 N 个编号功能点；例如 P0-4 是“跨JD原子要求归并与映射” | 通用缺陷优先级标签，或仅凭编号宣称功能已完成 |

## 跨阶段不变量

1. P0-1 定义抽取数据合同和语义决策规则（规则带稳定 ID），不直接产生业务数据。
2. P0-2 按整份 JD 执行结构化抽取并产生职责和原子要求；困难样例只用于评测。
3. P0-3 验证和改进原子要求的拆分粒度，不定义另一套数据类型。
4. P0-4 汇总选定范围内所有要求实例后统一执行要求归并与映射；职责文本中识别出的候选人条件可以进入 P0-4，`ResponsibilityItem` 本身不参与要求归并。
5. P0-4 不得覆盖或删除 `raw_name`、category、importance、proficiency、逻辑组、年限、evidence 或 confidence；代码和 Prompt 保持领域无关，不硬编码具体领域技能。
6. P0-4 归并批次必须绑定完整选定 JD、共同抽取器版本和归并输入指纹；输入变化不得复用旧批次。
7. 同义表达归并到同一标准要求项（等价由映射表达）；存在明确包含方向时由关系轮输出 `broader_than`（更宽泛 -> 更具体），无包含关系不输出边，信息不足输出 `uncertain` 弃权。
8. P0-8 正式 JD 样本范围必须显式冻结选中 JD，并由一个已通过验收的共同抽取器版本完整覆盖；不得以数据库全量、混合版本或部分成功范围代替。
9. P0-6 才按独立 JD 数去重统计；P0-7 通过要求映射回溯要求实例、证据和原始 JD。
10. 人工标准答案不得为迎合模型输出而修改，也不得因为模型输出与某个人工答案不同就修改 Prompt（DEC-015）；已用于调参的数据不得重新宣称为未见验证集。证据存在性不等于证据支持性，自动指标不得替代需要人工复核的语义判断；名称相似度只作 diagnostic，不得作为唯一 hard gate。
