# JD Requirements Insight 核心术语

本文是项目术语含义的唯一信息源。代码、测试、计划和 README 必须使用下列
标准术语；发现新术语、同词异义或定义冲突时先更新本文，再同步受影响内容。
本词典只固定容易导致业务语义漂移的核心术语，不复制代码类名、字段镜像、
数据库表定义或完整枚举；这些内容以 `app/schemas.py`、`app/models.py`
和标注规范为准。

## 数据与抽取

| 标准术语 | 固定含义 | 不表示 |
|---|---|---|
| JD | 一份岗位描述，是正式结构化抽取、持久化和后续统计的来源单位 | 一个困难样例或一条岗位要求 |
| 职责 | 入职后需要完成的一项可独立描述或验收的工作；发现段区分 responsibility 块，避免职责被误抽成候选人要求 | 候选人需要具备的条件 |
| 岗位要求 | 公司对候选人的一项技能、经验、学历、专业、行业知识或软能力条件 | 只表示技术技能，或岗位职责本身 |
| 证据 | JD 原文中连续出现、能够支持岗位要求及其字段判断的最小充分文本 | LLM 改写、跨段拼接或归并理由 |
| 内容哈希 | 对 JD 正文执行 Unicode NFKC 与空白规范化后计算的 SHA-256，用作内容级去重标识 | 修改数据库中的 JD 原文 |
| 抽取器版本 | `model_name + prompt_version + schema_version` 组成的抽取结果身份，用于验收、定稿、下游输入选择和 provenance 绑定 | 单独的 Prompt 版本或一次运行 ID |

## 原子化与归并

| 标准术语 | 固定含义 | 不表示 |
|---|---|---|
| 原子要求 | 按原子化规则表达的一条 `RequirementItem`，只包含一个可独立学习、分类、评价、匹配或统计的条件；固定复合要求可以整体保留 | 必须压缩成单个技术词 |
| 固定复合要求 | 已形成稳定整体含义，或拆分后会改变招聘条件原意的复合表达，例如“数据结构与算法” | 任意包含“和”“与”的长要求 |
| 要求实例 | 某份 JD、某个抽取结果中的一条具体原子要求，带原始名称、属性、逻辑组、年限、证据和置信度 | 跨 JD 共享的标准要求项 |
| 跨JD原子要求归并与映射 | 汇总选定范围内的全部要求实例，模型一次输出 canonical requirement 与来源实例分区，mappings 由确定性代码生成并保存 | 合并岗位职责、删除原始要求 |
| canonical 来源分区 | 模型单次聚类输出中每个 canonical 声明的来源实例归属（source_requirement_ids）；构成完整唯一覆盖，遗漏/重复/未知 ID 都是合同错误 | 由映射反推的归属、可被确定性代码修改的聚类 |
| 标准要求项（canonical requirement） | 多个语义相同的要求实例共同指向的跨 JD 统计口径 | 覆盖或删除原始要求实例 |
| 要求映射 | 要求实例到标准要求项的可追溯关联，保存映射理由和置信度；由来源分区确定性生成，每个实例必须且只能映射一次 | 修改 `raw_name`、抽取属性或原始证据 |
| 归并输入指纹 | 对选定 JD、共同抽取器版本、抽取记录和完整要求实例执行确定性序列化后计算的 SHA-256；与范围键、归并器版本共同构成归并批次身份 | 归并器版本或内容哈希 |
| 同一要求 | 表面名称不同但结合证据上下文后指向同一招聘条件；例如明确语境中的缩写、中英文名称和同义表达 | 上下位、组成或仅相关关系 |
| 独立JD计数 | 按标准要求项统计包含该项的不同 JD 数量；同一 JD 内多个要求实例只计一次覆盖；市场高频排序以独立 JD 数优先（实例数只作补充） | 删除同一 JD 内的重复要求实例 |
| importance 双口径 | 实例级（按原始 requirement instance 计数，诊断用）与 JD 级（按独立 JD 计数，同一 JD 按 must > preferred > mentioned > unknown 优先级只贡献一次，市场报告默认口径） | 把 JD 级分布当作实例级分布 |

## 验证

| 标准术语 | 固定含义 | 不表示 |
|---|---|---|
| 规则场景 | 领域中性的基础输入 + 确定性变换 + 期望属性，用于变形测试；不保存完整 expected extraction | 完整人工标准答案 |
| 变形测试 | 对同一基础输入应用确定性变换后比较两次抽取，检查事实集、块集合与字段不变性 | 多次运行稳定性 |
| 多次运行稳定性 | 相同输入独立运行多次，以候选块为锚点报告块对齐与漂移；只作 warning 供人工判断 | 语义准确性证明 |
| 人工规则审计 | 人工按规则 ID 检查输出是否违反规则、证据是否支持结论，记录违规与建议 | 自动字符串包含检查 |
| 证据存在性 | 单条证据经允许的文本规范化后可在对应 JD 原文中找到（自动 hard gate） | 证据足以支持结论 |
| 证据支持性 | 单条证据确实足以支持抽取名称和字段判断（人工复核） | 自动字符串包含检查 |
| 熟练度（三级） | Schema V3 抽取枚举：`unknown`（无明确程度或仅经验类表达）/ `basic`（了解、理解、熟悉、能够使用）/ `advanced`（掌握、熟练、扎实、精通、专家级）；原始程度词保留在 evidence | 候选人真实能力、`none`、旧五级值（当前流程明确拒绝并要求重新抽取） |
| positive-pair Jaccard | 两次归并运行同簇正实例对的 Jaccard，用于发现 cluster 拆分/合并 | 总 pairwise 一致性 |

## 项目范围

| 标准术语 | 固定含义 | 不表示 |
|---|---|---|
| MVP | 当前求职作品版的最小可信闭环：把真实 JD 转化为可统计、可追溯的市场要求报告 | 完整招聘产品、自动投递 Agent |
| P0-N | 仓库现有实验脚本使用的 v0.1 阶段标签，仅用于定位验收模块 | 当前实施阶段或通用缺陷优先级标签 |

## 流水线不变量

1. 抽取数据合同和语义决策规则使用稳定规则 ID，不直接产生业务数据。
2. 整份 JD 经两段式结构化抽取产生原子要求；responsibility 块不得产出岗位要求。
3. 归并汇总选定范围内所有要求实例并生成唯一映射；职责不参与归并。
4. 归并不得覆盖或删除 `raw_name`、category、importance、proficiency、逻辑组、年限、evidence 或 confidence；归并代码和 Prompt 保持领域无关，不硬编码具体领域技能。
5. 归并批次必须绑定完整选定 JD、共同抽取器版本（v0.10 + Schema V3）和归并输入指纹；输入变化不得复用旧批次。
6. 同义表达归并到同一标准要求项（等价由映射表达）；不确定时创建 singleton，不输出未映射状态。
7. 独立 JD 计数按标准要求项统计不同 JD 数，同一 JD 内多个实例只计一次。
8. 旧抽取版本与旧数据库结构不做兼容或迁移：遇到时明确提示备份原始 JD 并重新生成。
