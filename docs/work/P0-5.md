## 1. 目标与边界

### 目标

用人工标准答案分层衡量抽取、原子化、要求映射、字段和证据质量，并输出可定位的错误类型，避免用单一总分掩盖问题。

### 非目标

- 不用名称代理指标替代人工语义复核。
- 不为提高模型指标修改人工标准答案，不把私有标注或失败原文提交到 Git。
- 不在 P0-3、P0-4 通过验收前宣称端到端质量完成。

### 验收标准

1. 8～10 份标准答案按开发、回归和未见验证用途冻结并可复现选择。
2. 抽取、原子化、映射、字段和证据指标均单独报告，包含错误类型占比。
3. 未见验证集端到端原子要求 F1 不低于 70%，其他指标和失败案例如实记录。
4. P0-4 正式批次（规则合同与多次运行一致性）和人工证据支持性复核接入；评测函数有确定性测试且不调用外部服务。

## 2. 接口与不变量

- 数据集一旦用于调 Prompt 即转为开发/回归用途，不再作为下一轮未见验证集。
- 专有技术词保留，名称匹配采用确定性一对一规则；证据存在性和证据支持性分开报告。
- 归并评测必须显式选择批次，不能隐式使用“最新”结果。

## 3. 当前实现

- `app/evaluation.py`：纯离线指标函数（名称代理匹配、数量一致、字段准确率、证据存在率、映射准确率、关系 P/R/F1、错误摘要）。
- `app/cli.py`：`evaluate-cases` 支持 development/regression/validation 三个分组并按抽取器版本选择结果；`evaluate-consolidation` 显式绑定批次 ID 离线评测。
- 评测过程不调用模型；私有 golden 与详细失败案例不进入 Git。
