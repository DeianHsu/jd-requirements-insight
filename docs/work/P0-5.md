## 1. 目标与边界

### 目标

分层衡量抽取、原子化、要求映射、字段和证据质量，并输出可定位的错误类型，避免用单一总分掩盖问题。评测方法遵循 DEC-015：不再以人工完整答案 F1 作为正式 Prompt 验收门槛，正式质量证明迁移到规则符合性、稳定性与鲁棒性验证；人工负责规则制定与违规审计。

### 非目标

- 不用名称代理指标替代人工语义复核；不把名称相似度作为唯一 hard gate。
- 不为提高模型指标修改人工标准答案，不把私有标注或失败原文提交到 Git。
- 不在 P0-3、P0-4 通过验收前宣称端到端质量完成。

### 验收标准

1. 抽取验收按 P0-3 新协议执行（规则场景 + 变形测试 + 多次运行稳定性 + 人工违规审计），旧 Gold 分组只作 legacy 历史比较。
2. 抽取、原子化、映射、字段和证据指标均单独报告，包含错误类型占比；确定性代码的 expected output 只在测试解析器、Schema、证据校验时使用完整精确值。
3. 人工违规审计格式（rule_id/violation/severity/evidence/reason/recommended_action）生效。
4. P0-4 正式批次（规则合同与多次运行一致性）和人工证据支持性复核接入；评测函数有确定性测试且不调用外部服务。

## 2. 接口与不变量

- 已用于调参的样例只能作为开发/回归用途，不得重新宣称为未见验证集；旧 `annotation_cases.json` 已标记 `protocol=legacy_gold`、`status=historical`、`official_gate=false`。
- 专有技术词保留，名称匹配采用确定性一对一规则；证据存在性和证据支持性分开报告。
- 归并评测必须显式选择批次，不能隐式使用"最新"结果。

## 3. 当前实现

- `app/evaluation.py`：纯离线指标函数（名称代理匹配、数量一致、字段准确率、证据存在率、映射准确率、关系 P/R/F1、错误摘要）。
- `app/cli.py`：`evaluate-cases`（**legacy**，仅历史比较与案例分析，不得用于批准新 Prompt）、`evaluate-extractions`（**legacy**）、`validate-consolidation`（当前正式离线验证入口）。
- `app/extraction_validation.py`、`data/rule_scenarios/`、`scripts/experiments/p0_3/run_acceptance.py`：P0-3 新协议验证闭环（规则符合性、稳定性、变形测试）。
- 评测过程不调用模型；私有 golden 与详细失败案例不进入 Git。

## 6. 关键变更

- 验收协议随 DEC-015 迁移：人工完整 Gold 降级为 legacy 历史材料；正式验收改为规则符合性 + 稳定性 + 变形测试 + 人工违规审计；P0-5 不再以人工答案 F1 作为正式验收门槛。
