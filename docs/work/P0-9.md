## 1. 目标与边界

### 目标

为 P0 核心规则和高风险失败路径建立与风险相匹配的确定性测试，并以完整测试与 Ruff 作为 P0 整体及 P0-11 的完成门禁。

### 非目标

- 不用确定性测试判断 LLM 语义是否正确，不以测试总数作为验收目标。
- 不为了通过测试改变业务合同或人工标准答案。

### 验收标准

1. 导入、失败、合同、拆分、映射、关系、计数和证据查询关键路径均有确定性测试。
2. P0-10 报告生成具有最小可复现测试，测试不依赖真实私有数据。
3. 完整测试和 Ruff 通过，外部服务无真实调用，真实项目数据无修改。
4. 已知警告和暂缺覆盖如实记录；测试数量不替代各 P0 业务验收。

## 2. 接口与不变量

- 测试使用临时文件、虚构数据和临时 SQLite 数据库；有费用外部调用必须被替身隔离，测试套件不得产生真实调用。
- 单个测试验证一个清晰行为；缺陷修复应先增加可复现失败测试。

## 3. 当前实现

- `tests/` 全部当前测试文件：覆盖导入、抽取、Schema、迁移、两段式、归并批次身份/幂等/外键/关系合同/分块输出边界、实验脚本付费保护等。
- `pyproject.toml`：测试与 Ruff 配置。
- 已知警告：1 个来自 FastAPI TestClient 依赖链的 Starlette/httpx 弃用警告，不影响当前行为。
