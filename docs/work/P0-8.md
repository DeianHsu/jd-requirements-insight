## 1. 目标与边界

### 目标

在不改变 P0-2 稳定接口和数据语义的前提下，形成由 15～20 份真实目标岗位 JD 组成的正式 JD 样本范围。范围必须来源可追溯、筛选可解释、重复项已排除、导入可复现，并且全部 JD 具有同一个已通过验收的抽取器版本，供 P0-6 和 P0-10 进行正式规模验收。

### 背景

当前 5 份真实 JD 足以支持功能开发和小规模验证，但不足以承担 P0-6 和 P0-10 的正式规模验收。15～20 份 JD 仍是 MVP 阶段的**定向样本**，不是具有统计代表性的市场随机样本；后续结论必须限定在当前筛选范围内。

### 非目标

- 不自动爬取招聘网站，不建立通用采集平台。
- 不修改 P0-2 抽取数据合同、数据库结构或既有抽取语义。
- 不在 P0-8 中实现 P0-3 抽取优化、P0-4 要求归并、P0-6 统计或 P0-10 报告生成。
- 不为样本引入自动近似文本聚类或复杂样本版本系统；疑似转载和轻微改写由人工复核。

### 验收标准

1. 私有样本清单中冻结 15～20 个唯一已持久化 JD，数据库 ID 和内容哈希均可核对；扫描数、导入数和抽取数不得误作样本数量。
2. 每个选中 JD 满足纳入条件，来源类型明确且至少有一种私有可回查来源；排除项及理由有记录。
3. 相同内容重复导入不会新增记录；疑似转载、轻微改写和重复发布已人工复核，确认的重复项未进入正式 JD 样本范围。
4. 批量导入对错误文件给出文件级提示并隔离事务；修正后重试不会破坏已成功记录。
5. 15～20 个选中 JD 全部具有同一个已通过验收的抽取器版本，正式抽取成功数等于选中数、失败数为 0。
6. Develop 只保存脱敏汇总和材料路径，真实 JD、来源地址、数据库、原始响应和私有清单均未进入 Git。
7. 明确说明样本的公司、来源和岗位方向分布及已知偏差，并限定 P0-6/P0-10 结论只适用于当前筛选范围。

## 2. 接口与不变量

- “15～20 份”指当前正式 JD 样本范围中 15～20 个**唯一已持久化 JD**，不是扫描文件数、单次导入成功数或抽取结果数。
- 精确去重继续使用现有内容哈希：只规范化哈希输入，不改写持久化的 JD 正文。
- 单文件解析或校验失败不得回滚其他有效文件；失败项修正后可重复导入，已成功项必须幂等跳过。
- 当前样本清单（筛选条件、收集时间范围、选中 JD 的数据库 ID 和内容哈希、来源类型、纳入/排除理由、目标抽取器版本和抽取状态）属于**私有材料**，不进入 Git。
- 正式 JD 样本范围必须显式列出选中 JD，不得把数据库全部 JD 隐式等同于当前样本；只有数据库恰好仅含当前样本时才可以用 `--all` 代替显式 `--job-id`。
- 范围内每份 JD 必须存在**同一个已通过验收的抽取器版本**，正式抽取失败为 0；不得混合版本凑齐样本。正式抽取前若 P0-3 新方案通过验收，则全范围统一使用新版本。
- P0-4 仍负责用选定 JD、共同抽取器版本和完整要求实例生成归并输入指纹；P0-8 不另造归并批次身份。

### 筛选规则

纳入条件（同时满足）：

1. 岗位核心职责明确属于 LLM 应用、Agent 应用、RAG 应用或紧邻的 AI 应用工程方向；仅在任职要求中偶然提到 AI 不算目标岗位。
2. 招聘主体符合产品定位：面向产品或客户交付的初创公司、中型公司。
3. 正文完整、非测试或合成数据，并包含 `collected_at`、`company`、`title` 和可识别的来源类型。
4. 至少保留一种可回查来源：`source_url`、`source_image` 或等价的私有来源记录。

排除条件：

- 以基础模型预训练、纯算法研究、纯数据科学或纯平台基础设施为核心，且不承担 LLM/Agent/RAG 应用交付的岗位。
- 通用后端、产品、销售或运营岗位，仅在描述中附带提到 AI。
- 正文截断、关键元数据缺失、无法回查来源、测试数据或合成数据。
- 内容哈希相同的精确重复项，以及经人工确认属于同一招聘岗位的转载、轻微改写或重复发布项。

不预设城市、经验年限、岗位方向或来源平台的硬配额，但必须检查公司、来源和岗位方向是否过度集中并说明原因；同一公司存在多个确实不同的目标岗位时可以同时纳入，但须在私有筛选记录中说明差异。

## 3. 当前实现

- `app/ingestion.py`：Markdown 与 Front Matter 解析、Unicode NFKC + 空白规范化的 SHA-256 内容哈希、逐文件事务导入与文件级错误隔离。
- `app/cli.py`：`import-jds`（批量导入、幂等跳过、有限摘要）、`list-jds`。
- `tests/test_ingestion.py`、`tests/test_cli.py`：覆盖元数据解析、空白规范化、幂等和文件级错误隔离。

## 6. 关键变更

- 原计划：扩充到 15～20 份 JD 作为统计与报告输入。
- 发现的问题：数据库全量、混合版本或部分成功范围不能承担正式验收输入；轻微改写与转载无法自动识别。
- 当前决定：显式冻结“正式 JD 样本范围”（见 `docs/GLOSSARY.md`），私有清单记录选中项、内容哈希、来源、筛选依据和共同抽取器版本；不与 P0-3/P0-4 相互等待，可与二者并行推进。
- 影响范围：P0-8 只提供验收输入，不构成 P0-6/P0-10 实现代码的功能硬依赖。

## 7. 当前结论

导入、校验和去重能力正式可用（P0-2 已验收，`import-jds` 可复用）；样本收集与统一抽取尚未完成，当前 IN_PROGRESS。结论适用 implementation_revision：e121636。
