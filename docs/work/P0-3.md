## 1. 目标与边界

### 目标

验证并改进 P0-2 输出的职责与要求粒度，使复合表达按统一语义边界拆成可统计的独立项，不漏拆、不多拆，并保留正确原文证据。

### 背景

单阶段 Prompt 在职责业务粒度、非穷举示例和任选关系上反复出现过拆或欠拆。两段式候选把“发现原文候选”和“按规则判断结构”分离，以减少规则互相干扰（详见 `docs/DECISIONS.md` CASE-001）。

### 非目标

- 不在本功能内做跨 JD 同义归并、标准要求项统计或市场报告。
- 不因开发集指标较高就自动替换 P0-2 正式 Prompt。
- 不把真实 JD、人工标准答案或原始模型响应纳入 Git。

### 验收标准

1. 两段式结果通过 P0-1 合同、唯一覆盖和证据校验，选定真实 JD 运行 0 最终失败。
2. 开发集与回归集的职责/要求 F1、数量一致、任选关系和字段指标达到已冻结候选门槛且不牺牲已知关键边界；候选门槛对照采用多次运行统计口径（见 §6 关键变更）。
3. 未见验证集端到端原子要求 F1 不低于 70%（每次独立验收运行均须达标），并如实报告全部分层指标和失败案例。
4. 定向测试、全量测试和 Ruff 通过；正式版本只在验收 APPROVED 后替换。

## 2. 接口与不变量

- **最终结果仍使用 P0-1 `JobExtractionResult`**，不得修改其字段语义。
- 发现段候选必须被判断段唯一覆盖；证据必须来自原文。
- 先识别独立业务交付，再判断动作是否共同构成一项职责。
- 括号或“等”中的非穷举示例不自动成为要求；被条件直接修饰的具体技术名保留。

## 6. 关键变更

- 原计划：单阶段 Prompt 直接产出最终粒度。
- 发现的问题：V2.1 过拆（按动作拆分导致碎片化）、V2.2 过合（端到端整体保留导致召回下降），原 5 个验证集职责样例因参与 V2.2 设计转为回归集。
- 当前决定：采用发现段/判断段两段式候选；验证集按“每份现有 JD 的第一条实质职责”等预定义规则选取并经用户批准冻结，不得按模型表现挑选。
- **验收裁决口径（用户 2026-08-03 裁决）**：development 候选门槛对照采用多次运行统计口径——共执行 3 次独立验收运行（run1 已存在，补 run2/run3），development 各指标取 3 次中位数对照冻结门槛（要求/职责 F1 100%、数量一致 10/10、any_of 7/7、category 90.91%、proficiency 90.91%）；validation 端到端原子要求 F1 ≥70% 为硬门槛，每次独立运行均须达标；任何一次运行不得丢弃或与历史运行合并。已实测 temperature=0 存在输出波动，单次运行不达门槛不作为否决理由。
- 影响范围：候选只影响 `app/extraction_two_stage.py` 与实验脚本，正式抽取链路不受影响。
- **正式版本替换（用户 2026-08-03 裁决批准，提交 `1ab4bd0`）**：v0.6 由候选切换为正式抽取版本（`extract_job` 转发两段式），历史 V2.3.1 保留；development 中位数 2 项未达冻结门槛按已定口径不作为否决理由（详见 `docs/DECISIONS.md` DEC-014）。

## 7. 当前结论

v0.6 已通过正式验收（3 次独立运行 validation 端到端原子要求 F1 全部 ≥70%）并获批替换正式版本 Prompt V2.3.1（提交 `1ab4bd0`，详见 `docs/DECISIONS.md` DEC-014）。P0-5 的 P0-3 依赖已解除。已知限制：jd_003 的 case_020/case_021（端到端交付边界、上位单条列举）3 次验收全部失败，列入回归关注点。结论适用 implementation_revision：1ab4bd0（两段式核心实现源自 bdd8932）。
