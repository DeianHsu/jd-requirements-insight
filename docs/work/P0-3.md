## 1. 目标与边界

### 目标

验证并改进 P0-2 输出的职责与要求粒度，使复合表达按统一语义边界拆成可统计的独立项，不漏拆、不多拆，并保留正确原文证据；质量证明采用规则符合性（hard gate）+ 多次运行稳定性 + 规则场景变形测试 + 人工违规审计（DEC-015），不再以人工完整答案 F1 作为正式验收门槛。

### 背景

单阶段 Prompt 在职责业务粒度、非穷举示例和任选关系上反复出现过拆或欠拆。两段式候选把"发现原文候选"和"按规则判断结构"分离，以减少规则互相干扰（详见 `docs/DECISIONS.md` CASE-001）。

### 非目标

- 不在本功能内做跨 JD 同义归并、标准要求项统计或市场报告。
- 不因任何单一人工答案的差异修改 Prompt；不以稳定性冒充准确性。
- 不把真实 JD、人工标准答案或原始模型响应纳入 Git。

### 验收标准（新协议，DEC-015/DEC-016）

1. **Hard gates**：Schema 违规 0；证据违规 0；discovery 覆盖 100%；duplicate sentence coverage 0；judge 候选类型覆盖 100%（responsibility 块必须产出 responsibility、requirement 块必须产出 requirement、mixed 记录实际产出、excluded 块不得产出 must/preferred）；非法逻辑组 0；无依据明确事实 0（evidence_unattributed_items）；版本身份完整；运行完整性（expected/successful/failed 任何缺失）；格式变换不得产生实质事实丢失；无关输入不得改变原有候选块和原子事实。
2. **规则场景变形测试**（protocol 1.1）：`data/rule_scenarios/extraction_metamorphic_cases.json` 的 13 类场景期望属性全部满足；变换返回 `TransformationResult`（base→transformed 锚点映射支持一对多、预期变化区域），场景属性可定位到目标锚点（basic→advanced / basic→unknown / standalone→any_of / raw_name 跟随替换）；场景不保存完整 expected extraction。
3. **多次运行稳定性**：相同输入独立运行 ≥3 次，以候选块为锚点（sentence_indexes → span occurrence → kind → 覆盖集合）报告块对齐率、kind/字段/组成员一致性、未配对项与漂移块 ID；第一版作为 warning 报告实际基线，阈值待用户裁决。
4. **人工违规审计**：按规则 ID 审计输出是否违反规则、证据是否支持结论（evidence semantic support 只能由人工完成）；审计模板 `reports/templates/extraction-rule-audit.json`（字段：audit_id/extractor_version/scenario_or_job_id/rule_id/violation/severity/evidence_reference/reason/recommended_action/reviewer/reviewed_at；模板不包含真实 JD）。
5. 定向测试、全量测试和 Ruff 通过；正式版本替换只在 Track A 与 Track B 都通过并完成人工审计后裁决。

## 2. 接口与不变量

- **最终结果仍使用 P0-1 `JobExtractionResult`**，不得修改其字段语义。
- 发现段候选必须被判断段唯一覆盖；证据必须来自原文。
- 先识别独立业务交付，再判断动作是否共同构成一项职责。
- 括号或"等"中的非穷举示例不自动成为要求；被条件直接修饰的具体技术名保留。
- 旧 `evaluate-cases` / `evaluate_two_stage_results.py` 标记为 legacy：只用于历史比较和案例分析，不属于当前正式验收，不得用于批准新的 Prompt。

## 3. 当前实现

- `app/extraction_two_stage.py`：发现段、判断段、中间 Schema、唯一覆盖、证据校验和有限重试；正式版本 **v0.7**（`TWO_STAGE_PROMPT_VERSION`，与 `app/extraction.py` 的 `PROMPT_VERSION` 同步，测试锁定）；v0.7 Prompt 引用 P0-1 稳定规则 ID 并删除案例式补丁，v0.6 历史 Prompt 保留为 `LEGACY_DISCOVERY_SYSTEM_PROMPT_V06` / `LEGACY_JUDGE_SYSTEM_PROMPT_V06`。
- `app/extraction_validation.py`：确定性合同检查（Schema/覆盖/证据/类型化候选块覆盖/逻辑组/归属/身份）、以候选块为锚点的运行间比较（相同输入与变形输入两套对齐）、组内最佳原子项配对（类型隔离 → evidence 分组 → 字段得分贪心）、逻辑组结构比较（去临时 group_id，pairwise co-membership）、场景期望属性检查（含目标锚点定位）、hard gate/warning/diagnostic 分级验收报告；不调用外部模型。
- `data/rule_scenarios/extraction_metamorphic_cases.json`：protocol 1.1，13 个领域中性规则场景（格式、顺序、无关内容、重复、措辞、改名、拆句、相关技术、同级词、经验表达），不保存完整 expected extraction。
- `scripts/experiments/p0_3/run_acceptance.py`：**Track A** 验收脚本（显式使用 candidate v0.8 + Schema V3；`--execute` 完整验收 / `--dry-run` 预检；`--runs>=3`、`--max-attempts>=1` 门禁；base 与 transformed 均执行完整合同检查；运行完整性计数为 hard gate；报告记录 scenario_set_fingerprint/runs/max_attempts 等；不读取人工完整答案决定通过或失败）。
- `scripts/experiments/p0_3/run_real_jd_acceptance.py`：**Track B** 真实 JD 验收（显式选择 JD ID 或 `--all`；每份 JD 独立运行 ≥3 次；报告块对齐/项数漂移/字段一致性/组成员一致性/evidence attribution/proficiency distribution；与 v0.6 只做 diagnostic 对比；不自动执行 P0-4 归并；输出脱敏审计样本索引；原文与完整响应只写 `data/private/`）。
- `reports/templates/extraction-rule-audit.json`：人工违规审计记录模板。
- `scripts/experiments/p0_3/`：真实调用（`run_two_stage_extraction.py`，必须 `--execute`）与离线评测（`evaluate_two_stage_results.py`，**legacy**，仅作历史比较）。

## 6. 关键变更

- 原计划：单阶段 Prompt 直接产出最终粒度；开发/回归/验证集人工标准答案作为正式验收真值。
- 发现的问题：V2.1 过拆、V2.2 过合；少量人工 Gold 无法证明跨表达或跨领域泛化，且据 Gold 反复修改 Prompt 会形成隐藏训练信号（DEC-015）。
- 当前决定：两段式架构保持不变；**正式验收协议迁移为规则符合性 + 稳定性 + 变形测试 + 人工违规审计**（DEC-015）；v0.6 原批准保留并标注 `approved under legacy Gold protocol`；旧人工标注、F1 报告与审批历史降级为 legacy 历史材料。
- 版本隔离（本轮）：active = v0.6 + Schema V2；candidate = v0.8 + Schema V3；v0.7 为历史未批准候选版本（Git 历史承担复现）；验收脚本显式使用 `CANDIDATE_EXTRACTION_PROFILE`。
- 熟练度收缩（本轮）：FIELD-03 五级 → 三级（unknown/basic/advanced，DEC-016）；旧值读取时确定性映射，物理数据不重写。
- 验证框架修复（本轮）：变形比较使用 TransformationResult 锚点（一对多、重复句 occurrence）；原子项配对改为类型隔离 + evidence 分组 + 组内最佳匹配；逻辑组比较去临时 ID（pairwise co-membership）；check_contract 类型化候选块覆盖 + excluded 违规 + evidence 歧义；验收脚本增加参数门禁、运行完整性 hard gate、transformed 合同检查、dry-run 显式模式。
- 双轨道验收（本轮）：Track A 合成规则场景 + Track B 真实 JD，两个 Track 都通过并完成人工审计后才能讨论 v0.8 替换 v0.6。

## 7. 当前结论

状态 **PARTIAL**：active v0.6 + Schema V2 仍是当前正式可运行版本（原批准基于 legacy Gold protocol，DEC-014）；candidate v0.8 + Schema V3（三级熟练度）框架已实现并通过测试（218 passed、Ruff 通过），真实模型验收（Track A/B）尚未执行，因此不得标记 APPROVED。不得宣称语义准确率或三级熟练度的真实性已经得到证明；稳定性报告只作 warning 基线，阈值待用户裁决。
