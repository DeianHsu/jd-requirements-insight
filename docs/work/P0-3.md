## 1. 目标与边界

### 目标

验证并改进 P0-2 输出的职责与要求粒度，使复合表达按统一语义边界拆成可统计的独立项，不漏拆、不多拆，并保留正确原文证据。

### 背景

单阶段 Prompt 在职责业务粒度、非穷举示例和任选关系上反复出现过拆或欠拆。两段式候选把“发现原文候选”和“按规则判断结构”分离，以减少规则互相干扰（详见 `docs/DECISIONS.md` CASE-001）。

### 非目标

- 不在本功能内做跨 JD 同义归并、标准要求项统计或市场报告。
- 不因开发集指标较高就自动替换 P0-2 正式 Prompt。
- 不把真实 JD、人工标准答案或原始模型响应纳入 Git。

### 验收标准

1. 两段式结果通过 P0-1 合同、唯一覆盖和证据校验，选定真实 JD 运行 0 最终失败。
2. 开发集与回归集的职责/要求 F1、数量一致、任选关系和字段指标达到已冻结候选门槛且不牺牲已知关键边界。
3. 未见验证集端到端原子要求 F1 不低于 70%，并如实报告全部分层指标和失败案例。
4. 定向测试、全量测试和 Ruff 通过；正式版本只在验收 APPROVED 后替换。

## 2. 接口与不变量

- **最终结果仍使用 P0-1 `JobExtractionResult`**，不得修改其字段语义。
- 发现段候选必须被判断段唯一覆盖；证据必须来自原文。
- 先识别独立业务交付，再判断动作是否共同构成一项职责。
- 括号或“等”中的非穷举示例不自动成为要求；被条件直接修饰的具体技术名保留。

- `app/extraction_two_stage.py`：发现段、判断段、中间 Schema、唯一覆盖、证据校验和有限重试；两段式核心候选 v0.6（`TWO_STAGE_PROMPT_VERSION`），实现源自 `bdd8932`。
- `scripts/experiments/p0_3/`：真实调用（`run_two_stage_extraction.py`，必须 `--execute`）与离线评测（`evaluate_two_stage_results.py`，覆盖 development/regression/validation 三个分组、case_id 级失败案例与证据统计，提交 `6958d97`；失败案例表含多拆型 case——`1555124` 修复了 `exact` 字符串真值判断 bug，此前"数量不一致但预期项全部匹配"的 case 会被静默跳过）。
- **当前正式版本仍为 Prompt V2.3.1；v0.6 只是未接入正式流程的候选。**

已接受风险：旧 Git 历史仍含本次低敏感度验证样例与人工标注（无凭据、个人隐私或客户机密），用户已于 2026-08-02 明确接受，不再要求历史改写；防复发规则已生效（受跟踪文件私有指纹命中数 0）。

## 6. 关键变更

- 原计划：单阶段 Prompt 直接产出最终粒度。
- 发现的问题：V2.1 过拆（按动作拆分导致碎片化）、V2.2 过合（端到端整体保留导致召回下降），原 5 个验证集职责样例因参与 V2.2 设计转为回归集。
- 当前决定：采用发现段/判断段两段式候选；验证集按“每份现有 JD 的第一条实质职责”等预定义规则选取并经用户批准冻结，不得按模型表现挑选。
- 影响范围：候选只影响 `app/extraction_two_stage.py` 与实验脚本，正式抽取链路不受影响。

## 7. 当前结论

v0.6 候选的 validation 第 1 次独立验收已达标（端到端原子要求 F1 96.30% ≥ 70%，实现 revision bdd8932），但 development 候选门槛复现口径未确定、正式验收裁决未作出，**当前不能替换正式版本 Prompt V2.3.1**；P0-5 正式验收被阻塞。结论适用 implementation_revision：6958d97（两段式核心实现源自 bdd8932）。
