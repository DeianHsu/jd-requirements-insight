## 1. 目标与边界

### 目标

验证并改进 P0-2 输出的职责与要求粒度，使复合表达按统一语义边界拆成可统计的独立项，不漏拆、不多拆，并保留正确原文证据；质量证明采用规则符合性（hard gate）+ 多次运行稳定性 + 规则场景变形测试 + 人工违规审计（DEC-015），不再以人工完整答案 F1 作为正式验收门槛。

### 背景

单阶段 Prompt 在职责业务粒度、非穷举示例和任选关系上反复出现过拆或欠拆。两段式候选把"发现原文候选"和"按规则判断结构"分离，以减少规则互相干扰（详见 `docs/DECISIONS.md` CASE-001）。

### 非目标

- 不在本功能内做跨 JD 同义归并、标准要求项统计或市场报告。
- 不因任何单一人工答案的差异修改 Prompt；不以稳定性冒充准确性。
- 不把真实 JD、人工标准答案或原始模型响应纳入 Git。

### 验收标准（新协议，DEC-015）

1. **Hard gates**：Schema 违规 0；证据违规 0；discovery 覆盖 100%；duplicate sentence coverage 0；judge candidate coverage 100%；非法逻辑组 0；无依据明确事实 0；版本身份完整；格式变换不得产生实质事实丢失；无关输入不得改变原有候选块和原子事实。
2. **规则场景变形测试**：`data/rule_scenarios/extraction_metamorphic_cases.json` 的 10 类场景期望属性全部满足；场景不保存完整 expected extraction。
3. **多次运行稳定性**：相同输入独立运行 ≥3 次，以候选块为锚点报告块对齐率、kind/字段一致性、未配对项与漂移块 ID；第一版作为 warning 报告实际基线，阈值待用户裁决。
4. **人工违规审计**：按规则 ID 审计输出是否违反规则、证据是否支持结论；审计格式（rule_id/violation/severity/evidence/reason/recommended_action）见 `docs/annotation/README.md`。
5. 定向测试、全量测试和 Ruff 通过；正式版本替换只在真实模型验收完成后裁决。

## 2. 接口与不变量

- **最终结果仍使用 P0-1 `JobExtractionResult`**，不得修改其字段语义。
- 发现段候选必须被判断段唯一覆盖；证据必须来自原文。
- 先识别独立业务交付，再判断动作是否共同构成一项职责。
- 括号或"等"中的非穷举示例不自动成为要求；被条件直接修饰的具体技术名保留。
- 旧 `evaluate-cases` / `evaluate_two_stage_results.py` 标记为 legacy：只用于历史比较和案例分析，不属于当前正式验收，不得用于批准新的 Prompt。

## 3. 当前实现

- `app/extraction_two_stage.py`：发现段、判断段、中间 Schema、唯一覆盖、证据校验和有限重试；正式版本 **v0.7**（`TWO_STAGE_PROMPT_VERSION`，与 `app/extraction.py` 的 `PROMPT_VERSION` 同步，测试锁定）；v0.7 Prompt 引用 P0-1 稳定规则 ID 并删除案例式补丁，v0.6 历史 Prompt 保留为 `LEGACY_DISCOVERY_SYSTEM_PROMPT_V06` / `LEGACY_JUDGE_SYSTEM_PROMPT_V06`。
- `app/extraction_validation.py`：确定性合同检查（Schema/覆盖/证据/逻辑组/归属/身份）、以候选块为锚点的运行间比较、场景期望属性检查、hard gate/warning/diagnostic 分级验收报告；不调用外部模型。
- `data/rule_scenarios/extraction_metamorphic_cases.json`：10 个领域中性规则场景（格式、顺序、无关内容、重复、措辞、改名、拆句、相关技术），不保存完整 expected extraction。
- `scripts/experiments/p0_3/run_acceptance.py`：新协议验收脚本（默认不调用外部模型，`--execute` 显式授权；`--runs 3` 独立运行；每次结果独立文件；报告记录 model/prompt/schema/input fingerprint/run identifier/timestamp；不输出完整私有 JD；不读取人工完整答案决定通过或失败）。
- `scripts/experiments/p0_3/`：真实调用（`run_two_stage_extraction.py`，必须 `--execute`）与离线评测（`evaluate_two_stage_results.py`，**legacy**，覆盖 development/regression/validation 三个分组，仅作历史比较）。

## 6. 关键变更

- 原计划：单阶段 Prompt 直接产出最终粒度；开发/回归/验证集人工标准答案作为正式验收真值。
- 发现的问题：V2.1 过拆、V2.2 过合；少量人工 Gold 无法证明跨表达或跨领域泛化，且据 Gold 反复修改 Prompt 会形成隐藏训练信号（DEC-015）。
- 当前决定：两段式架构保持不变；**正式验收协议迁移为规则符合性 + 稳定性 + 变形测试 + 人工违规审计**（DEC-015）；v0.6 原批准保留并标注 `approved under legacy Gold protocol`；旧人工标注、F1 报告与审批历史降级为 legacy 历史材料。
- v0.6 → v0.7（本轮）：Prompt 引用稳定规则 ID（RESP-*、REQ-*、GROUP-*、FIELD-*、EVID-*、COVER-*），删除针对单个历史 case 的补丁式示例（迁移为规则场景中性改写），压缩为少量领域中性正反例；覆盖、证据和禁止推断要求未降低。
- 新增验证闭环：`app/extraction_validation.py`（确定性）、`data/rule_scenarios/`（场景）、`scripts/experiments/p0_3/run_acceptance.py`（验收入口）。

## 7. 当前结论

状态 **PARTIAL**：v0.6 仍是当前正式可运行版本，原批准基于 legacy Gold protocol（DEC-014，状态标注 approved under legacy Gold protocol）；新协议（规则符合性、稳定性、鲁棒性验证）的确定性框架已实现并通过测试（174 passed、Ruff 通过），真实模型验收尚未执行，因此不得标记 APPROVED。不得宣称语义准确率已经得到证明；稳定性报告只作为 warning 基线，阈值待用户裁决。
