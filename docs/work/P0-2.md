## 1. 目标与边界

### 目标

把已导入 JD 按 P0-1 数据合同转换为可持久化、可追溯、可评测的结构化抽取结果，对结构或证据错误进行有限重试和明确记录。

### 非目标

- 不在本功能内优化原子粒度指标或跨 JD 归并。
- 不开发复杂前端、业务 API 或自动爬取。

### 验收标准

1. 真实 JD 可按统一数据合同完成模型抽取并持久化。
2. 结构错误、JSON 错误和证据不存在会触发有限重试，最终失败有明确原因。
3. 模型、Prompt、Schema 和抽取结果具有可追溯版本信息，版本间互不覆盖。
4. 小规模真实验证最终失败为 0，关键确定性路径有自动化测试。

## 2. 接口与不变量

- 使用 P0-1 正式数据合同，不在抽取阶段生成标准要求项；输出证据必须能在对应 JD 原文中定位。
- **抽取器版本** = `model_name + prompt_version + schema_version`，是抽取结果的身份；重跑不得覆盖其他版本结果。
- 当前正式版本：两段式 **v0.7** + 抽取数据合同 V2 + DeepSeek V4 Flash（`temperature=0`、JSON Object 模式）；v0.6 在 legacy Gold protocol 下批准（DEC-014），v0.7 起 Prompt 引用 P0-1 稳定规则 ID 并删除案例式补丁（DEC-015）；V2.3.1 与 v0.6 作为历史版本保留。
- 有费用调用必须显式执行。

## 3. 当前实现

- `app/extraction.py`：确定性请求配置、JSON 解析、合同校验、证据校验和有限重试；`extract_job` 转发两段式流程（`app/extraction_two_stage.py` 的发现段+判断段），`PROMPT_VERSION=0.7` 与 `TWO_STAGE_PROMPT_VERSION` 同步（测试锁定）；历史 V2.3.1 的 `SYSTEM_PROMPT` 与 v0.6 的 `LEGACY_*_V06` Prompt 保留供实验对比与历史复现。
- `app/extraction_two_stage.py`：发现段/判断段中间合同、唯一覆盖、证据校验和有限重试；`extract_job_two_stage_with_discovery` 暴露发现段结果供验证与审计。
- `app/extraction.py`、`app/cli.py`：选择 JD、持久化成功结果、显示有限失败信息。
- `app/config.py`：LLM 配置。

## 6. 关键变更

- 原子化策略：先识别独立交付再决定合并动作、区分非穷举示例与直接点名技术（`docs/DECISIONS.md` DEC-007），语义边界规则持续有效。
- v0.6 → v0.7（本轮）：判断段与发现段 Prompt 引用 P0-1 稳定规则 ID（RESP/REQ/GROUP/FIELD/EVID/COVER），删除针对单个历史 case 的补丁式示例（历史内容迁移到 `data/rule_scenarios/` 中性改写场景），保留少量领域中性正反例；覆盖、证据和禁止推断要求未降低。

## 7. 当前结论

正式可用。两段式架构（discovery 全局扫描 + judge 局部判断 + 确定性代码负责合同和证据）保持不变；正式抽取版本由 v0.6 推进为 v0.7（Prompt 规则化），历史 v0.6 与 V2.3.1 结果保留。旧 F1 指标是 legacy protocol 历史证据；正式质量证明迁移到新 P0-3 的规则符合性、稳定性与鲁棒性验证（DEC-015）。v0.7 真实模型验收完成前，v0.6 仍是当前正式可运行版本。
