## 1. 目标与边界

### 目标

把选定 JD 范围内的全部要求实例动态归并到可统计的标准要求项，保存同义映射、组成/相关/上下位关系、来源证据和模型依据，并使每个结果批次可复现。

### 背景

纯字符串规则无法处理开放领域同义和关系，代码预置技能词表又不能扩展到新职业。LLM 负责提出语义归并，确定性代码负责完整性、冲突、身份和审计（`docs/DECISIONS.md` DEC-009、DEC-010）。

### 非目标

- 不修改 P0-1 `RequirementItem` 字段或预置 Python 等具体技能。
- 不建设独立发布版本系统，不允许失败时留下部分正式批次。
- 不为通过模型输出而放松完整覆盖、全局唯一或关系图合同。

### 验收标准

1. 149 条实例完整映射且 0 失败，任一失败不留下部分批次。
2. 归并判定（标准项、同义映射、关系）由模型自主提出，不设人工金标准；验收以规则合同（标准 3）通过、同输入多次运行一致性如实报告、正式批次完成后人工抽样复核归并合理性（争议点记录判断理由）为准。
3. 批次身份、幂等、输入变化、外键、全局唯一、关系互斥/无环和显式批次评测合同全部通过。
4. 定向测试、全量测试和 Ruff 通过；详细结果保存到 `reports/P0-4/`。

## 2. 接口与不变量

- **输入范围**：选定范围内覆盖全部 JD 的同一抽取器版本及其全部要求实例；批次身份 = 范围键 + 归并器版本（`model + prompt + schema`）+ 归并输入指纹（SHA-256）。输入变化不得复用旧批次。
- 相同输入重复执行不调用模型；输入或抽取器版本变化产生新批次。
- 所有输入实例恰好获得映射；标准项规范化名称全局唯一；关系类型互斥且图无环；任一阶段失败不写入批次（内存合成完整结果后统一校验、一次性持久化）。
- 内部模型调用允许分阶段或分块，但外部批次身份、完整覆盖、全局校验和原子持久化合同不得放松。

## 3. 当前实现

- `app/consolidation.py`：三阶段输出边界（标准项生成 → 按 `mapping_chunk_size`（默认 `CONSOLIDATION_MAPPING_CHUNK_SIZE = 50`）分块映射 → 关系生成），各阶段独立有限重试、映射块块级覆盖校验；合成后统一执行合同、名称唯一、引用完整、关系互斥/无环与完整覆盖校验。149 实例映射轮拆为 50+50+49。
- 关系轮使用专用系统提示 `RELATION_SYSTEM_PROMPT`（聚焦关系判定、part_of 优先与跨层级限制）；标准项与映射轮共用 `CONSOLIDATION_SYSTEM_PROMPT`。当前候选 Prompt 版本 v2.1（v1.8 → v1.9 → v2.0 → v2.1 迭代过程见报告）。
- 客户端与解析容错均在 `app/consolidation.py`：`candidate_requirement_ids: null` 规范化为空列表（与 `[]` 语义等价，`review_required` 缺候选仍拒绝）。
- `scripts/experiments/p0_4/run_small_scale_precheck.py`：75 实例小规模预检入口。
- `data/consolidation_cases.json`（私有）：历史阶段6起草的参考标注草案，2026-08-03 用户裁决不再作为验收金标准，降级为参考材料；映射准确率/关系 P/R/F1 仅作参考诊断。
- 已解决的历史问题：SQLite 外键未启用导致孤立记录风险（已开启并验证 0 违规）、输入身份不完整导致旧结果误复用（输入指纹）、关系 Precision/Recall/F1 评测与关系图冲突检测、指定批次离线评测 CLI（`evaluate-consolidation`）。

## 6. 关键变更

- 原计划：149 实例单次完整模型请求，对同一完整请求有限重试。
- 发现的问题：连续 3 次正式验收未形成批次，最后一次为约 50KB JSON 截断（单次请求超 20 实例时输出可达 15KB 以上，接近截断线）。
- 当前决定（2026-08-03）：
  1. 分阶段/受控分块输出边界（标准项 → 分块映射 → 关系），内存合成完整结果后统一全局校验、原子持久化；合成阶段冲突整批失败不追加重试。
  2. **验收口径变更（用户裁决）**：归并判定由模型自主提出，不再对照人工金标准；历史阶段6起草的参考标注草案（`data/consolidation_cases.json`）降级为参考材料；验收改为规则合同 + 同输入多次运行一致性如实报告 + 人工抽样复核。原草案在 734/735 part_of 等判定上与模型稳定分歧，4 轮 Prompt 调整无收敛，根源是主观归类差异而非模型错误。
- 影响范围：只改变内部模型输出边界与验收口径；外部批次身份、完整覆盖、全局校验和原子持久化合同未放松。

## 7. 当前结论

确定性能力（批次身份、输入指纹、外键、关系评测、图冲突、指定批次评测）已通过验收标准 3 的既有支持与测试；分阶段/分块输出边界已实现并修复截断问题。验收口径已按用户 2026-08-03 裁决调整为“规则合同 + 多次运行一致性 + 人工抽样复核”，草案标注降级为参考材料，原关系门槛分歧不再阻塞。**149 实例正式验收未启动**，启动并完成后才能作为 P0-6 的稳定数据源。恢复条件：用户授权正式验收。结论适用 implementation_revision：2af2ee3。
