## 0. P0-4A 与 P0-4B 拆分

P0-4 在代码合同、评测、文档和状态管理中明确区分两个逻辑阶段（同一执行流程）：

| 阶段 | 输入 | 输出 | 服务对象 | 验收 |
|---|---|---|---|---|
| P0-4A 实例归并（核心事实层） | requirement instance | instance -> canonical requirement（每个实例恰好 mapped 一次） | P0-6 高频统计、独立 JD 计数、证据追溯、市场报告 | 合同 + 完整覆盖 + 变形测试 + 多次运行稳定性（§1） |
| P0-4B 标准项层级（解释组织层） | canonical requirement pairs | broader -> narrower | 报告分组、层级展示、用户理解 | 图合同 + 稳定性 + 稀疏度 + 下游不变性 + 人工抽样审计（§1） |

**P0-4B 不阻塞 P0-6**：统计只依赖映射；P0-4B 失败时 P0-4A 事实层仍原子落库（`hierarchy_status=failed`），不得伪装成整批成功。

## 1. 目标与边界

### 目标

把选定 JD 范围内的全部要求实例动态归并到可统计的标准要求项（P0-4A），并对标准要求项建立服务于报告组织的明确包含层级（P0-4B），保存来源证据和模型依据，使每个结果批次可复现。

### 背景

纯字符串规则无法处理开放领域同义和关系，代码预置技能词表又不能扩展到新职业。LLM 负责开放语义判断（归并、包含方向），开发者负责关系定义、数据合同、约束、审计和下游行为（`docs/DECISIONS.md` DEC-009、DEC-010、DEC-012、DEC-013）。

### 非目标

- 不修改 P0-1 `RequirementItem` 字段或预置 Python 等具体技能。
- 不建设人工 Gold 数据集；来源和审核过程无法确认的旧评测夹具（`data/consolidation_cases.json`）已删除，不再作为项目资产和验收依据。
- 不引入训练、微调、分类器或 embedding 聚类。
- 不扩展为完整知识图谱：正式关系只有 `broader_than`，`equivalent` 由映射表达，`none` 不持久化，`uncertain` 不创建边，`related_to` 已删除。
- 不为通过模型输出而放松完整覆盖、全局唯一或关系图合同。

### 验收标准（Hard gate / Warning / Diagnostic 分级）

**P0-4A Hard gate：**

1. 完整覆盖：`input_instance_count = mapping_count`、coverage=100%、重复映射=0、未知标准项引用=0；每个输入实例恰好 mapped 一次（`unmapped`/`review_required` 不再是正常业务状态，不确定时由模型创建 singleton canonical requirement）。
2. 标准项合同：ID 唯一、规范化名称唯一、名称非空、每个标准项至少一个实例、rationale/confidence 满足 Schema、不生成输入中没有依据的具体要求、原始名称/证据/来源保持不变。
3. 批次身份与幂等：绑定模型、Prompt 版本、Schema 版本、范围与输入指纹；同输入同版本重复执行直接复用；输入或版本变化产生新批次；失败批次不得伪装为可复用成功批次。
4. 原子持久化：标准项/映射块/全局校验任一失败不落库；关系阶段失败时 P0-4A 事实层仍原子落库且 `hierarchy_status=failed`；外键违规 0。
5. 分块完整性：chunk 只影响调用边界，最终内存全局引用与覆盖校验；扩充到 15～20 份 JD 无需改变合同（不把 149 写成永久标准）。

**P0-4A 变形测试 Hard gate（真实模型验收门槛）：**

6. 输入顺序不变性：随机打乱输入顺序，实例对 pairwise co-clustering agreement 高置信 ≥95%、全部 ≥90%、coverage 每次 100%。
7. 分块大小不变性：chunk_size 25 与 50 两次运行，高置信 agreement ≥95%、全部 ≥90%、coverage 100%。
8. 精确重复一致性：名称/证据/字段完全相同的两个实例必须映射到同一 canonical。
9. 保守回退：语义可能相关但无法确认等价的实例分别形成 singleton，不强制合并、不进入系统失败状态。
10. 无关输入隔离：新增明显不同维度的实例不引起原有 cluster 大面积变化。
11. 输入扩展一致性（Diagnostic）：稳定子集单独运行 vs 完整输入，记录 cluster 变化，不设硬门槛。

**P0-4A 多次运行稳定性 Hard gate：**

12. 固定模型/Prompt/Schema/输入指纹/temperature，3 次独立非缓存运行：高置信 pairwise co-clustering agreement ≥90%、全部 ≥85%、coverage 每次 100%、结构违规每次 0；记录 canonical 数量范围、最大 cluster、singleton 数、漂移实例 ID。
13. Warning：canonical 数量最大最小差 >20%、最大 cluster >全部实例 20%、singleton 比例异常、高置信实例明显漂移、同 cluster 名称差异异常大。

**P0-4B Hard gate：**

14. 图合同 100%：正式边只允许 `broader_than`（方向 broader -> narrower）；`related_to`/`is_a`/`part_of` 数量为 0；`none`/`uncertain` 不持久化；自环、重复边、反向冲突、有向环、未知节点引用均为 0。
15. 稳定性：3 次运行共同出现边的方向一致率=100%、两两 edge Jaccard ≥70%、结构违规 0。
16. 稀疏度：`edge_count / node_count ≤ 2`（>2 Warning、>3 验收失败除非逐项说明）；记录最大出入度、根节点、孤立节点、uncertain 数。
17. 下游不变性：不加载/全加载/只加载高置信层级三种状态下，instance_count、distinct_job_count、source_job_set、importance_count、evidence_count 差异全部为 0。
18. 人工抽样审计：抽查是否明显荒谬、违反关系定义、普通相关误判为包含、方向错误、缺理由、应弃权未弃权。
19. 机器可读验收报告生成（hard gate / warning / diagnostic 分级）；全量测试与 Ruff 通过。

### 分级验收

- **Implementation acceptance**：代码合同、自动化测试、分块与事务、变形测试框架、验收报告生成、当前范围真实运行能力全部就绪后达成；可说明"实现已具备验收条件"，但不宣称完成最终规模验收。
- **Scale acceptance**：P0-8 扩充至 15～20 份真实 JD 后，在正式范围重新执行全部真实模型验收项。当前 5 份 JD / 149 条实例不是永久规模标准。

## 2. 接口与不变量

- **输入范围**：选定范围内覆盖全部 JD 的同一抽取器版本及其全部要求实例；批次身份 = 范围键 + 归并器版本（`model + prompt + schema`）+ 归并输入指纹（SHA-256）。输入变化不得复用旧批次。
- 相同输入重复执行不调用模型；输入或抽取器版本变化产生新批次。
- 所有输入实例恰好获得 mapped 结果（P0-4A）；标准项规范化名称全局唯一；正式关系只有 `broader_than`（方向 broader -> narrower），互斥且无环（P0-4B）；标准项/映射块失败不写入批次；关系阶段失败降级保存事实层（`hierarchy_status=failed`）。
- 内部模型调用允许分阶段或分块，但外部批次身份、完整覆盖、全局校验合同不得放松。
- 旧关系类型已从枚举删除；模型输出 `is_a`/`part_of` 时解析层规范化为 `broader_than`（方向反转），输出 `related_to` 时拒绝并要求修正。

## 3. 当前实现

- `app/consolidation.py`：三阶段输出边界（标准项生成 → 按 `mapping_chunk_size`（默认 `CONSOLIDATION_MAPPING_CHUNK_SIZE = 50`）分块映射 → 关系生成），各阶段独立有限重试；映射块级校验强制全部 mapped（非 mapped 拒绝并要求模型创建 singleton）；关系阶段失败可降级（`degrade_hierarchy_failure`）；合成后统一执行合同、名称唯一、引用完整、方向冲突、关系互斥/无环与完整覆盖校验。
- 关系轮使用专用系统提示 `RELATION_SYSTEM_PROMPT`（判断顺序：可归并不建边 → broader_than → none 不输出 → uncertain 弃权，含等价/相似、包含/相关的领域无关正反例）；映射轮 `CONSOLIDATION_SYSTEM_PROMPT` v4.0（保守归并、全 mapped、singleton 回退）。版本 `model|prompt:4.0|schema:2.0`。
- `app/requirement_consolidation.py`：`RequirementRelationType` 只含 `broader_than`（正式）与 `uncertain`（判断状态）；`RequirementMappingStatus` 保留旧枚举值仅为读取旧批次；`RequirementConsolidationResult` 含 `uncertain_relations` 与 `hierarchy_status`（success/failed）。
- `app/consolidation_validation.py`：合同违规检测（coverage/重复/未知引用/空 cluster/自环/重复边/方向冲突/环）、`co_clustering_agreement`（实例对同簇一致性，不依赖临时 canonical ID）、`edge_jaccard`/`direction_consistency`（规范化名称对齐节点）、`fact_projection`（下游统计投影）、`build_acceptance_report`（hard gate/warning/diagnostic 分级机器可读报告）。
- 持久化：`requirement_relations` 表只写正式 `broader_than` 边；`none` 无记录、`uncertain` 仅存在于 `raw_response` 审计输出；`job_consolidations.hierarchy_status` 记录 P0-4B 状态；数据库迁移删除重建可再生的关系表（旧枚举数据移除）、为批次表补充层级状态列。
- CLI：`consolidate-requirements`（含 hierarchy 状态输出）、`list-consolidations`、`validate-consolidation`（合同 + 图稀疏度 + 事实投影，不依赖人工 Gold）。
- 实验脚本：`run_small_scale_precheck.py`（小规模预检，无 Gold 依赖）、`run_acceptance.py`（真实模型验收：3 次独立运行 + 顺序/分块变形 + 稳定性 + 验收报告，`--execute` 显式授权）。
- **真实验收后修复（HEAD）**：验收发现标准项生成轮可能输出无人引用的噪声标准项——已确定性剔除（`1f383f7`）；发现映射轮可能幻觉输出清单外标准项 ID——块级校验拒绝清单外 ID 并要求模型反馈修正（`1f00720`）；剔除噪声标准项时同步删除指向它的关系边，避免孤儿边污染关系图（`f3aea5f`）。
- 版本兼容说明：抽取侧候选版本 v0.8 + Schema V3（三级熟练度，DEC-016）不影响 P0-4 业务逻辑；旧 Schema V2 结果经读取时映射仍可作为归并输入，归并侧无需修改。
- 已解决的历史问题：SQLite 外键未启用、输入身份不完整、归并 JSON 截断（分块输出边界）、关系过度生成（`related_to` 删除 + 稀疏度警戒）、来源不明旧夹具依赖（已删除）。

## 6. 关键变更

- 原计划：149 实例单次完整模型请求 → 分阶段/受控分块输出边界（标准项 → 分块映射 → 关系），内存合成后统一校验、原子持久化。
- 验收口径变更（用户 2026-08-03 裁决）：归并判定由模型自主提出，不设人工金标准（DEC-012）。
- **关系模型收缩（本次）**：删除 `related_to`（普通相关不建边）；`part_of`/`is_a`/上下位统一为 `broader_than`（下游行为相同）；`equivalent` 由实例→标准项映射表达不建边；`none` 不持久化；`uncertain` 允许弃权不创建边。P0-4A 要求每个实例恰好 mapped 一次（不确定时 singleton 回退），废弃 `unmapped`/`review_required` 的正常业务状态。
- **删除旧夹具**：`data/consolidation_cases.json`（来源和审核过程无法确认）已删除；13 实例映射准确率、关系 P/R/F1、84.62%/80% 门槛、"人工标准答案"等全部移除；`evaluate-consolidation` 命令替换为 `validate-consolidation`。
- **4A/4B 状态分离**：`hierarchy_status` 记录 P0-4B 状态；P0-4B 失败不阻塞 P0-4A 落库与 P0-6 统计。
- **验证体系重构**：不再验证"是否匹配人工唯一答案"，改为合同 + 完整覆盖 + 变形测试 + 多次运行稳定性 + 关系图稀疏度 + 下游统计不变性 + 异常可诊断性，分级为 hard gate / warning / diagnostic。
- Prompt 2.1 → 4.0，Schema 1.0 → 2.0（旧版本批次不误复用）；数据库：关系表删除重建（可再生产物）、批次表补 `hierarchy_status` 列（可重复执行迁移）。
- 影响范围：关系类型、验收维度与评测入口变化；外部批次身份、完整覆盖、全局校验合同未放松。

## 7. 当前结论

实现已具备 implementation acceptance 条件并通过真实 LLM 验收（授权执行）：P0-4A 全 mapped 合同与 singleton 保守回退、P0-4B broader_than 图合同（方向冲突/环/重复/自环全部拒绝）、4A/4B 状态分离、旧夹具完全移除；验收发现并修复无人引用噪声标准项（`1f383f7`）、映射轮幻觉标准项 ID（`1f00720`）并同步删除关系边（`f3aea5f`），修复后全量 218 项测试与 Ruff 通过。

**第 1 次正式验收结果（2026-08-03，deepseek-v4-flash、prompt:4.0、149 实例/5 JD）**：
- **P0-4A 全部 Hard gate 达标**：合同 coverage=100%、结构违规=0；3 次独立运行 pairwise co-clustering 高置信 99.41~99.95%（门槛 ≥90%）、全部 99.32~99.91%（门槛 ≥85%）；输入顺序变形 99.90%+、分块大小变形 99.89%+（门槛 ≥95%/90%）；下游统计不变性 passed（三类差异均为 0）。**P0-4A 已具备解除 P0-6 阻塞的条件（§1 标准 1~13 全部满足）**。
- **P0-4B 未达标（不阻塞 P0-6）**：edge Jaccard 11.11~31.25%（门槛 ≥70%）、方向一致率 91.67%（run0-1）；canonical 数量波动 105~135（>20% warning）；uncertain=0（模型从不弃权）；稀疏度 edge/node=0.786 达标。P0-4B 关系稳定性需后续改进（更保守的 Prompt/置信度过滤/更强模型），改进后重新运行验收。

状态为 `implementation complete, scale acceptance pending`：P0-8 扩充至 15～20 份 JD 后需重新执行真实模型验收（§1 标准 6~18 + 异常报告）；P0-4A 在当前 5 JD 范围已满足解除 P0-6 阻塞的条件。结论适用 implementation_revision：f3aea5f。
