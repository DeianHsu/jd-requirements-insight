# JD Skill Insight｜项目路线图

> 核心目标：完成一个可评测、可追溯、可演示的 JD 岗位市场要求分析系统，证明能够把 LLM 放进真实业务流程并产出可靠结果。

## 一、项目定位与范围

面向 AI 应用工程、LLM 应用开发和 Agent 工程岗位的可信市场要求分析系统：把非结构化 JD 转化为可统计、可追溯的岗位要求数据。重点不是“做一个招聘系统”，而是证明能够识别 LLM 在信息抽取中的粒度、分类、证据和评测问题，并用工程方法把非结构化文本转化为可验证、可统计的数据。

MVP 只建设以下核心闭环，不同时扩展招聘产品、个人匹配系统和完整 Agent 系统：

```text
15～20份真实JD
  → 抽取数据合同约束的结构化抽取
  → 复合要求原子化
  → 跨JD原子要求归并与映射
  → 高频要求统计
  → 统计结论追溯原始证据
  → 分层评测与错误分析
  → Markdown市场分析报告
```

简历匹配分、LangGraph、Tool Calling、RAG 问答、FastAPI 业务接口和前端页面不属于 P0 核心闭环。

目标岗位：LLM 应用开发工程师、AI 应用开发工程师、初级或转型方向的 AI Agent 开发工程师、RAG 应用工程师。目标公司：有真实产品和客户的小型创业公司、有一定规模的中型公司；主动规避大厂和小作坊式管理的小公司。

## 四、P0 完成定义

P0 只有同时满足以下条件才可以标记为完成（条目细节以各 P0 工作文档验收标准为准）：

1. 至少 15 份真实目标岗位 JD 完成导入和结构化抽取；
2. 抽取数据合同和人工标注规范明确且与代码一致；
3. 复合要求可以原子化，每个要求实例可追溯地映射到标准要求项，并保存关系类型、映射依据和原始证据；
4. 高频统计按独立 JD 计数，并区分必需、加分和普通提及；
5. 每个统计结论可以追溯到具体 JD 和原文片段；
6. 8～10 份人工标准答案划分开发集和验证集，分层指标及失败案例被真实记录；
7. 核心规则具有确定性测试，全部测试与 Ruff 检查通过；
8. 可以生成一份真实数据驱动的 Markdown 市场分析报告；
9. README、架构说明和演示脚本与实现保持一致。

## 五、评测分层设计

评测必须分开报告抽取、原子化、要求映射、字段和证据质量，不能用单一总分替代。数据集划分、指标含义和错误复核方式以 [annotation/DATASET_EVALUATION.md](annotation/DATASET_EVALUATION.md) 为准；验收目标为验证集端到端原子要求 F1 不低于 70%，并如实报告其他分层指标和失败案例。
