# 项目计划

## 目标

把真实 JD 转化为**可统计、可追溯的市场要求报告**：导入 → v0.8 + Schema V3
结构化抽取 → 抽取质量验证 → requirement instance 归并为 canonical
requirement → 独立 JD 统计 → 原文证据追溯 → Markdown 市场分析报告。

## 六个当前阶段

| 阶段 | 目标 | 状态 |
|---|---|---|
| P0-1 数据合同与语义规则 | 抽取数据合同（Schema V3 三级熟练度）、要求/职责/逻辑组语义规则、证据合同 | ✅ 已完成 |
| P0-2 v0.8 结构化抽取 | 两段式（发现段 + 判断段）、证据校验、有限重试、幂等持久化 | ✅ 已完成（真实模型验证待 P0-3B） |
| P0-3A 规则场景验证 | 领域中性场景 + 确定性变换，合同检查与变形属性检查 | ✅ 流程就绪（真实运行待授权） |
| P0-3B 真实 JD 验证 | 显式选择 JD、重复运行、合同/漂移检查、异常项索引 | ✅ 流程就绪（真实运行待授权） |
| P0-4 要求事实归并 | instance → canonical → 唯一映射；合同校验、positive-pair Jaccard、漂移与变形检查 | ✅ 流程就绪（v0.8 输入验收待执行） |
| P0-5 市场统计、证据追溯与 Markdown 报告 | `app/market_analysis.py` 统计模块已完成；`generate-report` 与证据追溯报告待实现 | 🟡 进行中 |

## 当前下一步

1. 定点修正 P0-3A 暴露的问题（验证器锚点匹配假阳性 + 真实模型问题清单）；
2. 重新执行 P0-3A 规则场景真实验收；
3. 通过后对单份真实 JD 执行 P0-3B；
4. 单份验证通过后扩大到三份 JD；
5. 三份验证通过后持久化 v0.8 + Schema V3 抽取结果；
6. 执行 P0-4 预检、正式验收和正式归并；
7. 验收通过后实现 `generate-report`。

## MVP 完成条件

- 15～20 份真实 JD 完成 v0.8 抽取、归并与统计；
- `generate-report` 输出含独立 JD 数、importance 分布与原文证据追溯的
  Markdown 报告；
- 全量自动化测试与 Ruff 通过（自动化测试是所有阶段的共同完成条件）；
- README 与演示随最终报告交付。

## 明确不做

- 不维护旧抽取版本（v0.6/v0.7/V2.3.1）与旧 Schema 兼容——只支持
  v0.8 + Schema V3，旧数据明确拒绝并要求重新生成；
- 不做层级关系（P0-4B）——已删除，不进入统计与报告；
- 不建设 Web 服务、Agent 编排（LangGraph）、RAG 检索；
- 不做人工标准答案（Gold）评测——验证采用规则场景、合同检查与
  人工规则审计；
- 不自动迁移旧数据库——遇到旧结构提示用户备份重建。

## 硬依赖

- 付费 LLM 调用（抽取、归并）必须显式 `--execute` 确认；
- 真实 JD 与私有材料不提交 Git。
