# 功能目标与边界

验证并改进P0-2产出的职责和原子要求粒度，确保复合条件不漏拆、不多拆，并保留正确证据与逻辑组。P0-3不定义新的要求类型，也不执行跨JD要求归并。

# 当前状态

部分完成（暂停中）。开发集的要求名称F1、职责F1、数量一致和`any_of`均为100%，类别准确率90.91%，熟练度准确率86.36%；回归集职责F1为78.26%，数量一致2/5。V2.3.1报告决定暂停继续堆叠单体Prompt规则。两段式（发现/判断）实验已归档：回归集职责F1提升至92.31%（超越基线78.26%），开发集要求F1未追平（峰值91.95% vs 100%）；详见`reports/P0_3_TWO_STAGE_EXPERIMENT.md`。Codex审计已补齐两段式发现合同的确定性覆盖校验，但修复后没有重新执行付费模型回归，因此历史指标不能视为修复后版本已重新验收。

# 稳定事实

- 原子化以能否独立学习、分类、评价、匹配或统计为判断基础。
- 固定复合要求或拆分后失真的表达整体保留。
- 非穷举示例不建立封闭`any_of`；被候选条件直接修饰的具体技术名逐项保留。
- 职责先识别独立交付，再判断多个动作是否属于同一职责。
- 开发集和回归集已经参与设计，不能宣称为新的未见验证集。
- 正式抽取仍使用V2.3.1；两段式v0.5只是待恢复实验，除非同时保住要求侧基线和职责侧增益，否则不得替换正式Prompt。
- 两段式发现合同必须先证明全文每个分句恰好归属一个候选块，再进入判断段；覆盖检查失败不得通过Prompt结果“容错”或后处理静默修正。

- `docs/annotation/REQUIREMENTS.md`、`RESPONSIBILITIES.md`：粒度规则。
- `tests/test_extraction.py`：Prompt边界和实验测试。
- `reports/PROMPT_V2_ANALYSIS.md`至`PROMPT_V2_3_1_ANALYSIS.md`：历史实验；`reports/P0_3_TWO_STAGE_EXPERIMENT.md`：两段式归档。
- `docs/DEEPSEEK_CONTINUATION.md`：跨模型冷启动时使用的Codex审计差异、建议恢复顺序和提示词；P0-3状态仍以本handoff为准。

# 数据合同与不变量

- 原子化结果仍使用P0-1的`RequirementItem`和`ResponsibilityItem`。
- 多个原子项可以共享同一连续证据，但不得拼接不连续文本。
- 不按顿号、“和”或“与”机械拆分。
- 不因模型当前输出修改人工标准答案。
- 两段式发现结果的块ID唯一，分句索引非负、有序且连续；全文每个分句必须且只能归属一个块，原文片段必须对应声明索引。

# 测试与验证

当前工作树全量110项测试和Ruff通过；两段式实验12项专项测试覆盖重复分句、重复块ID、负索引、非连续合并、片段对应和重试，实验脚本测试覆盖私有输出边界和显式`--execute`。这些测试证明确定性合同和脚本边界，不等于修复后已重跑真实模型；P0-3业务质量结论仍是历史困难样例指标和Prompt报告中的阶段结论。

# 未完成事项与已知问题

- 回归集职责召回和数量一致尚未达到验收目标（两段式已改善，V2.3.1仍为正式Prompt）。
- 熟练度准确率仍低于目标。
- 两段式要求侧未追平V2.3.1；恢复时从v0.5继续，补要求规则细节1-2轮后可预期追平。
- 新验证集待创建（当前开发集/回归集已参与设计）。
- 下一轮实验门槛需在运行前冻结。建议至少保持开发集要求名称F1和`any_of`为100%、类别不低于90.91%、熟练度不低于86.36%，并保持两段式回归集职责F1不低于92.31%、数量一致不低于3/5；这些是候选门槛，不是已经通过的结果。
- 正式接入还需要P0-5按规则建立未见验证集，并记录正式Prompt切换与回滚边界。

# 继续开发入口

先读取本handoff、`reports/P0_3_TWO_STAGE_EXPERIMENT.md`、两个粒度规范、`app/extraction_two_stage.py`和`app/extraction.py`中V2.3.1的Prompt规则；跨模型接手再读取`docs/DEEPSEEK_CONTINUATION.md`。恢复条件：新领域冷启动、数据扩充后V2.3.1质量不达标，或用户明确授权继续两段式实验。

恢复时按小步骤执行：

1. 保持V2.3.1为正式基线，先运行确定性测试并用修复后的覆盖校验复现单份JD，不修改正式抽取入口。
2. 最多做1～2轮判断段要求侧规则补齐，重点验证原子化、任选关系、类别和熟练度；职责侧不做同步大改。
3. 每轮先记录版本、少量输入、指标和失败原因；小规模预检不计正式验收，不据此标记完成。
4. 候选门槛全部达到后，由P0-5建立并冻结未见验证集，再执行正式验收；一旦用该数据调参，它即转为开发集或回归集。
5. 新验证集、全量测试和Ruff全部通过后，才评审是否把两段式接入正式抽取并同步下游；否则保留为实验，P0-3继续标记`partial`。
