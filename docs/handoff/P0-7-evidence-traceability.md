# 功能目标与边界

让每个统计结论能够回到对应JD、公司、岗位、重要程度、原始要求名称和连续原文证据。P0-7负责查询和展示追溯链，不负责决定要求是否同义或计算频率。

# 当前状态

部分完成。JD正文、来源元数据、职责和要求的逐条证据已经持久化；标准要求项到要求实例的持久化映射、统计查询和报告展示尚未实现。

# 稳定事实

- P0-2已经保存JD来源、原始正文和逐条连续证据。
- `raw_name`和证据必须保留，不能被P0-4标准名称覆盖。
- 普通运行日志不能替代业务追溯关系，也不得保存JD正文或完整证据。

# 实现与文件入口

- `app/models.py`：现有JD、抽取结果、职责和要求关系。
- `app/extraction.py`：抽取结果持久化。
- `app/database.py`：现有数据库结构。
- P0-4、P0-6的持久化和查询文件尚未建立。

# 数据合同与不变量

- 追溯链必须通过稳定ID连接标准要求项、要求映射、要求实例和JD。
- 展示可以截取必要信息，但业务数据层必须保留完整连续证据。
- 不在日志、公开文档或终端错误摘要中泄露真实JD正文和完整证据。

# 测试与验证

现有测试覆盖JD、职责、要求和证据持久化，但没有统计结论到证据的端到端查询测试。

# 未完成事项与已知问题

- 依赖P0-4映射持久化和P0-6统计结果合同。
- 尚缺证据查询接口、分页或摘要策略及报告展示。

# 继续开发入口

先确认P0-4和P0-6的稳定ID与结果结构，再增加最小查询合同和端到端测试。测试使用虚构JD与证据，不读取真实数据库内容。
