# 功能目标与边界

汇总选定范围内全部`RequirementItem`对应的要求实例，把指向同一招聘条件的表达归并到标准要求项，并保存可追溯映射及必要的非同义关系。减少的是跨JD统计口径，不删除来源记录。

# 当前状态

部分完成，修复暂停中。输入版本身份、选定范围完整性、SQLite外键、关系假阳性指标和关系图冲突已完成确定性修复；Prompt v1.7小规模真实验证达到预设指标。3次正式完整验收均未产生可评测批次，连续验收失败已达到3次，按约定停止继续修复和模型调用。历史3次失败必须保留；只有用户明确授权恢复实施后才开始新的验收计数周期，讨论方案或只读检查不构成付费调用授权。P0-4不得标记完成，也不得作为P0-6稳定输入。

# 稳定事实

- P0-4输入是要求实例；`ResponsibilityItem`本身不参与要求归并。
- 职责文本中的候选人条件必须先由P0-2抽取为`RequirementItem`。
- 同义表达归并到同一标准要求项；`is_a`、`part_of`和`related_to`只建立关系，不触发归并。
- 同一表面词可以因证据上下文不同而映射到不同标准要求项。
- 代码与Prompt必须领域无关，不硬编码具体领域技能（有自动化测试断言）。
- 批次实际身份是范围键+归并器版本+归并输入指纹；新增JD、抽取版本或要求内容变化后会创建新批次。
- 选定JD必须全部存在同一目标抽取器版本；CLI必须显式选择`--all`或`--job-id`。
- LLM负责开放语义归并，确定性代码负责批次身份、范围完整性、合同、冲突、持久化和评测；不得为绕开大响应失败而放松完整覆盖、全局唯一或关系图合同。
- 即使未来把模型调用拆成多个阶段，只有完整映射和关系通过整体校验后才能原子持久化；中间候选不是正式归并批次。

# 数据合同与不变量

- `RequirementOccurrence`必须完整携带原始`RequirementItem`和来源定位。
- P0-4不得覆盖或删除`raw_name`、类别、重要程度、熟练度、逻辑组、年限、证据或抽取置信度。
- 每条要求实例必须且只能产生一个处理结果。
- 标准要求项ID和规范化名称不得重复；映射和关系不得引用未知ID。
- `related_to`反向重复视为同一关系；标准要求项必须有已映射来源。
- 同一标准要求项对的关系类型互斥；`is_a`和`part_of`不得形成有向环。
- SQLite连接必须启用外键，旧批次迁移不得删除或覆盖历史结果。

# 测试与验证

全量110项测试与Ruff通过；Prompt v1.7相关定向28项通过。真实数据库副本连续初始化两次后保留5个历史批次、5个隔离指纹，外键开启且0违规。正式`evaluate-consolidation`命令对历史批次5复算得到映射84.62%（11/13）、关系Precision 66.67%（4/6）、Recall 80%（4/5）、F1 72.73%；本轮3次正式验收均未形成新批次。

理想工程验收还必须证明：相同输入重复运行不调用模型，输入或抽取器版本变化产生新批次；任一模型阶段失败不留下部分批次；离线评测显式绑定批次ID；定向测试、全量测试和Ruff全部通过。这些工程门槛不能替代下节已固定的真实业务指标。
