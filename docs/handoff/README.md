# 阶段交接文档规则

本目录保存可提交到Git的工程阶段交接，使新Codex会话或开发者不依赖历史聊天即可恢复项目状态。

## 创建时机与命名

每个独立开发阶段完成、冻结或明确暂停时，在运行阶段验收后创建一份handoff，并与该阶段最终改动一起提交。文件名使用`YYYY-MM-DD-阶段英文短名.md`，已提交handoff不得改写为新的项目状态；后续变化创建新文件。

## 内容要求

每份handoff必须包含以下一级标题：

1. `阶段目标`
2. `已完成内容`
3. `修改文件`
4. `当前架构状态`
5. `数据契约`
6. `测试与验证`
7. `已知问题与限制`
8. `下一阶段任务`
9. `下一阶段注意事项`

内容以代码、Git差异和实际测试为依据，只记录接手工作所需的当前工程事实。禁止复制完整真实JD、模型JSON、Golden数据、密钥、私人材料或大段历史报告；需要时只记录文件路径、case ID和指标摘要。

## 阶段完成流程

1. 检查`git status`和最近提交，确认修改范围。
2. 运行与阶段风险匹配的测试和静态检查。
3. 按本模板创建handoff，记录实际命令与结果。
4. 检查敏感信息、文档链接和待提交差异。
5. 使用描述性commit message提交阶段代码、测试、说明和handoff。
