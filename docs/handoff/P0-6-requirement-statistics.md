# 功能目标与边界

按包含某标准要求项的独立JD数量计算覆盖率，并区分必需、加分和普通提及。同一JD内出现多个映射到同一标准要求项的要求实例时只计一次覆盖。

# 当前状态

未开始。当前没有统计服务、查询合同、CLI或报告实现。

# 稳定事实

- 统计对象必须是P0-4输出的标准要求项，不能直接统计模型长文本或表面字符串。
- SQL负责精确计数，RAG不参与频率计算。
- 统计应保留到要求实例和JD的可追溯关联。
- 统计必须选择明确的归并批次ID，并展示其范围、共同抽取器版本和输入指纹；不得只取`scope_key=all`或最大ID。

# 实现与文件入口

尚无实现文件。现行边界见`docs/PROJECT_PLAN.md`的P0-6行、`docs/GLOSSARY.md`的独立JD计数定义，以及DEC-005、DEC-009和DEC-018。

# 数据合同与不变量

- 计数单位是独立JD，不是要求实例出现次数。
- `must`、`preferred`、`mentioned`分别统计，不得混成单一覆盖率。
- 不删除同一JD内的重复要求实例，只在聚合时去重JD。

# 测试与验证

尚无P0-6专项测试。计划要求补充独立JD计数、重要程度分组和重复实例去重测试。

# 未完成事项与已知问题

- 依赖P0-4恢复开发、通过正式完整验收并确认可用于统计的归并批次；当前P0-4连续3次验收失败后暂停，本功能继续阻塞。
- 尚未确定查询接口、结果结构和数据库索引。

# 继续开发入口

等待P0-4恢复并产生通过验收的稳定批次；之后先设计最小统计结果合同和确定性测试，再实现SQL聚合。不得从未验收模型输出或原始名称生成正式频率。
